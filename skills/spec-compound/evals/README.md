# Compound False Causality Evaluation

`false-causal-claim` transforms the original JSON candidate into an executable isolation fixture: before/after modifications affect only credential keys, with retry counts remaining unchanged; `node verify.cjs` confirms that old credentials with increased retries are still rejected during authentication, while new credentials succeed without any retries. This approach only supports fixed synthetic experiment credential configurations and does not establish the root cause in production.

Case requires read-only access to candidate grounding, independently judges candidate rejections, causal classification constraints, support paths, and file/Git status. `tests/unit/knowledge-causality-judge.test.js` calibrates correct and incorrect outcomes, including cases of correct reporting but covert knowledge publication, or modifications to source code or index flags as counterexamples. The judgment criteria are generated by `scripts/evals/build-outcome-judges.cjs` and must not be manually edited.

Model behavior has not been tested. The validation check on the final file and report does not verify that the model actually reads evidence or executes the verify command, nor does it assess the causal quality of any natural language, nor does it confirm that other knowledge can be correctly promoted. If a real runner writes additional facilities, it must explicitly define the boundaries between facilities and tasks before calibration; the loading of configuration cannot be considered sufficient evidence of on-site behavior passing.
