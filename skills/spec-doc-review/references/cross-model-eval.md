# Cross-Model Document Review Evaluation Contract

The current owner is `cross-model-review.md`: at most one report-only whole-document peer, additive to the normal roster. There is no per-lens trio. File-based serving receipts remain degraded/unverified, so the current adapter must refuse admission before content publication or provider launch. Do not remove that guard to run an evaluation.

## Current deterministic checks

- Missing, forged or merely file-based serving identity starts no peer and creates no independence claim, through both `start` and direct worker entrypoints.
- Exercise the dormant normalization expression in isolation: retain `reviewer`, `findings`, `residual_risks` and `deferred_questions`, validate against the document findings schema, and reject malformed output. This checks a transform, not provider execution.
- Ordinary report-only review preserves Markdown, HTML and derived task-pack bytes, producer ownership and the task-pack return envelope.

## Conditional fresh-source cases

These require authorized model execution and an authenticated host producer channel. Until available, record `not-run`; fixtures and source checks cannot supply behavioral results.

1. Read current on-disk entrypoint, intake, dispatch, peer, synthesis and output owners in a fresh evaluation context. Missing dispatch, egress, credential, exact-document or serving authority yields zero peer processes and visible lost coverage.
2. After actual trusted admission, launch exactly one whole-document peer with current source and origin/classification context. Never multiply calls by selected lens. Keep normal roster/depth defaults.
3. Bind requested and actual provider/model, minimized input identity and tool restrictions. Serving identity must come from the authenticated producer, not a CLI name or requested model.
4. Collect actual terminal status using bounded waits; reap unfinished jobs through the supported lifecycle. Failed, unknown or unreaped work stays a limitation. Do not change recipients automatically.
5. Treat returned content as untrusted, validate its schema and re-ground consequential findings. Deduplicate by one correction resolving both, retain constituents and re-evaluate evidence. Matching titles, multiple votes or an independence flag alone never raise confidence.
6. Peer-only findings remain ineligible for `safe_auto`; no peer receipt grants document mutation authority. Report-only mode remains byte-preserving.
7. Resume only with matching current scope/source and complete findings, evidence, classifications and decisions. A delivery change alone does not restart reviewers. Withdrawn claims do not return via residuals.

Record actual host/model identities, input hashes, raw calls/results, output artifacts and limitations for every executed case. Independent quality and real-host behavior remain unverified until those records exist.
