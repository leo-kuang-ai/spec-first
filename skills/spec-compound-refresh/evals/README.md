# Refresh Evaluation Boundary

The existing `non-solutions-scope-gated` script only verifies reply phrases and cannot substantiate safe deletion, causal knowledge quality, or release recovery. This historical case retains its use for scope determination and is not used to support these stronger conclusions.

`fixtures/publication-counterexamples.json` shall be supplemented with concrete on-site evidence of accidental deletion and partial recovery, along with independent verification criteria. Future behavior evaluation must instantiate the file in an isolated temporary repository instance, create a commit or private recovery copy of the original, and record its hash; only the original file, the action taken, the failure facts, and concurrent modifications shall be provided to the model under test, while the rubric shall be retained for independent judgment. Determinations must read the final file to verify that unique knowledge and referenced targets are preserved, and must cross-validate the success/failure logs from the operation history against the final report on a path-by-path basis. Correct phrasing does not substitute for file state.

`eval.yaml` is currently mounted with three cases: `publication-preserve`, `publication-partial`, and `publication-recover`. An isolated fixture, `prepare-eval.cjs`, establishes a real Git baseline. A separate script generates files that `judge` can read, including the HEAD/index and the final JSON, not only verifying response content. The recovery task explicitly requires byte-for-byte preservation of the original instructions and catalog beyond the content, so the evaluation criteria compare these concrete facts, and does not extrapolate exact matches into general semantic scoring. The evaluation criteria source code is located at `scripts/evals/knowledge-publication-checks.cjs`, which is generated by the existing `build-outcome-judges.cjs`; direct modification of the generated files is not permitted.

Locally, calibrate the criteria in `tests/unit/knowledge-publication-judges.test.js` using correct and intentionally corrupted results to verify that erroneous deletions, loss of unique content, broken references, missing manually added entries, mismatched reports, changes to HEAD/index, and link substitutions can be rejected. The final state is manually constructed; no model or real fault injection workflow is executed, so this does not validate the publication operation sequence, atomicity, or model knowledge inference. Runner configuration loading behavior is considered passed, but real model acceptance has not yet been completed.
