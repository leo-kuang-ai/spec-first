# Project Profiles

Read only when changes occur in the local rules, governance, catalog, or source/runtime generator of the target repo that affect the patch. Portable core does not depend on this file.

## Discovery

Read in authority order:

1. target repo's `AGENTS.md`, `CLAUDE.md`, or explicit project guidelines;
2. The canonical Skill source root declared in the project;
3. governance/registry/catalog generator;
4. tests, logs, and the current runtime are used solely for validation or drift evidence.

Project profile must specify source, producer, consumer, authority, and failure mechanisms. Stay in `preview-only` mode when the canonical owner cannot be found.

## Spec-First Profile

In the spec-first repo:

- Skill source is `skills/<skill-name>/`;
- workflow/standalone/internal delivery is managed by `src/cli/contracts/dual-host-governance/skills-governance.json`;
- Claude command metadata source in `templates/claude/commands/spec/`;
- `docs/catalog/runtime-capabilities.md` is a read-only catalog generated by the generator;
- `.claude/`, `.codex/`, `.agents/skills/`, `.cursor/`, `.kiro/`, `.qoder/`, `.opencode/` are generated runtime surfaces;
- source triggers updates to tests, necessary docs, and `CHANGELOG.md`; runtime reconstructs via `spec-first init`.

When adding a new user-visible Skill, first update source/governance, then run `npm run docs:runtime-catalog` and the project-approved runtime projection. Do not treat catalog or runtime patch as source change.

## Non-Spec-First Projects

Only use rules declared in the target repo. Spec-first governance JSON, command template, catalog, or runtime projection shall not be created unless explicitly requested by the user for adoption of these mechanisms in the project.

## Multiple Projects Or Sources

A single invocation allows only one mutation target. When multiple repos, multiple canonical candidates, or source/runtime conflicts exist:

- Report candidates and evidence separately;
- not batch apply;
- Request user to select target/source owner, or keep as validate-only.
