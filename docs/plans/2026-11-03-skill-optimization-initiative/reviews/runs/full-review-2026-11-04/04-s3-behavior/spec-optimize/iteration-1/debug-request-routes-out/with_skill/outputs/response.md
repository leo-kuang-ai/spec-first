## 崩溃根因（已复现证实）

`src/server.js:10` 的 `JSON.parse` 裸露在 `'end'` 事件回调里，没有 try/catch。任何畸形或截断的请求体都会抛出未捕获 `SyntaxError`，整个进程退出。复现日志：

```
SyntaxError: Expected double-quoted property name in JSON at position 12
    at JSON.parse (<anonymous>)
    at IncomingMessage.<anonymous> (src/server.js:10:37)
```

「偶发」的原因：只有当某个客户端恰好发了坏数据（弱网截断、客户端 bug、curl 敲错、扫描器探测）才触发，服务端日志里只剩进程消失。

顺带发现两个同源的隐藏问题：

- **静默数据损坏**：`body += c` 把每个 TCP chunk 单独按 UTF-8 解码，中文等多字节字符跨分包时被切成 U+FFFD。复现中同一份合法 JSON 存进去变成 `���午咖啡`——不崩溃但数据坏了，且取决于分包时机，同样难复现。
- **请求流无 `'error'` 兜底**。

## 修复内容（`src/server.js`）

- 请求体改为 Buffer 收集、`Buffer.concat` 后一次性按 UTF-8 解码（消除多字节损坏）
- `JSON.parse` 包 try/catch，坏请求返回 400，进程不受影响
- 补 `req.on('error')`，客户端中途断开时只丢弃该条请求
