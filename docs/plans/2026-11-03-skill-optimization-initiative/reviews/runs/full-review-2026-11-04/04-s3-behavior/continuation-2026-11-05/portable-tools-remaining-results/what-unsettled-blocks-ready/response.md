按 spec-plan 完成了 Phase 0 清点，先同步事实，然后有一个必须由你拍板的问题。

**仓库现状**
- 已有代码是一个演示级记账服务：`src/server.js`（25 行，Node CommonJS）——`POST /entries` 记一笔、`GET /entries` 列出，数据存内存（重启即丢），无分类、无汇总、无多用户。
- 没有任何上游需求产物：`docs/plans/`、`docs/brainstorms/` 都不存在 → 本轮走 spec-plan 的 bootstrap（引导式规划）路线。

**卡点（产品级阻塞）**

“做成什么样、给谁用、算成功”属于 WHAT（产品定义）。spec-plan 的规则明确：WHAT 在这个深度缺失时，我不能把缺口悄悄包装成“假设”就照常输出一份“能开工”的计划——形态和用户会直接改变计划里的每个实施单元。所以按流程必须先问你怎么走（**单选，回复 A / B / C 即可**）：

- **A. 先走需求探索（正规上游路线是 `spec-brainstorm`）**——用多轮探索把目标用户、形态、成功标准系统定清楚，再出计划。注意：本机目前只装了 `spec-plan`，没装 `spec-brainstorm`，选 A 需要你先安装它，或接受我在本会话里用几轮提问做轻量版探索。
- **B. 现在拍板，我直接出可开工计划（推荐，最快）**——你再回答 1~2 个单选题（目标用户、产品形态），这些决策会记录为“用户已定”，我随即产出 implementation-ready 的实施计划。
- **C. 你不拍板，我按显式假设出计划**——我选最合理的方向，但所有未确认的 WHAT 会明确标注为“假设 + 方向风险”；计划本身能开工，方向错了返工风险由你承担。

选哪个？
