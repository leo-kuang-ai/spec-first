# 35 个现役 Skill 的职责与产物

截至 2026-11-20，当前工作树的 `skills/*/SKILL.md` 与 `src/cli/contracts/dual-host-governance/skills-governance.json` 注册项逐名一致，共 **35 个项目 Skill**：16 个工作流命令、15 个独立 Skill、4 个仅供内部调用的辅助 Skill。`_shared`、个人安装的插件和宿主生成镜像不计入。

下表沿用历史审查批次：第一批 9 个、第二批 17 个、第三批 9 个。第一批已逐文件审查，质量建议见[决策表](skill-decisions.md)；第二、三批仅列现役职责，不表示已经审完。本次校准不改变原 38 项计划名册或冻结审查证据。

| 批次 | Skill | 解决什么问题 | 交给谁、交付什么 |
|---|---|---|---|
| 一 | `using-spec-first` | 判断当前请求该走哪个入口 | 给请求者一个入口和下一步；不产生技术方案 |
| 一 | `spec-brainstorm` | 将已有想法澄清成需求，分出已定事项和待决问题 | 给负责人和规划者仅含需求的统一计划，不代表可以开工 |
| 一 | `spec-prd` | 为既有系统编写、完善或只读验证增量需求 | 给产品与规划者 PRD 或就绪诊断，含业务验收与阻塞事项 |
| 一 | `spec-plan` | 将明确目标转为有依据的实现或研究方案 | 给评审和执行者取舍、改动单元与验证办法 |
| 一 | `spec-write-tasks` | 将已定本地方案拆成可选任务包，或验证现有任务包 | 人读任务卡，实施方读结构化任务合同 |
| 一 | `spec-doc-review` | 判断需求、方案或任务文档能否支撑下一步 | 给作者有依据的发现及处置建议，区分建议与已修改 |
| 一 | `spec-work` | 完成明确实现请求、方案或有效任务包 | 给调用方实际变更、验证结果、残留事项及提交状态 |
| 一 | `spec-debug` | 定位故障、回归或失败原因 | 给报障者诊断证据；授权修复时另交修复与复验结果 |
| 一 | `spec-code-review` | 检查变更中的缺陷、回归和验证缺口 | 给开发者合并判断；给调用方结构化发现，默认不修代码 |
| 二 | `spec-ideate` | 尚未选定方向时生成和比较候选想法 | 给决策者候选方向与选择依据 |
| 二 | `spec-prototype` | 用可运行体验回答尚未确定的行为或视觉问题 | 给体验者一次性原型，不能冒充正式实现 |
| 二 | `spec-pov` | 对外部技术采用、文档方向或已有备选方案作判断 | 给决策者有项目依据的取舍意见 |
| 二 | `spec-simplify-code` | 在保持行为的前提下简化近期变更 | 给维护者更清楚的代码改动 |
| 二 | `spec-optimize` | 针对有可测指标的正常系统比较优化方案 | 给负责人基线、变体结果与保留建议 |
| 二 | `autoresearch` | 围绕可检验目标反复试验，有条件地保留或丢弃变更 | 给委托者实验结果及停止依据，不自动批准发布 |
| 二 | `spec-polish` | 在浏览器中检查并迭代界面细节 | 给开发者界面调整及观察结果 |
| 二 | `spec-dogfood` | 按分支或 PR 的改动范围试用受影响的流程 | 给交付方体验问题、处理结果与剩余风险 |
| 二 | `spec-test-browser` | 内部辅助：运行受改动影响的浏览器检查 | 向调用方返回页面行为证据；不负责根因诊断 |
| 二 | `spec-test-xcode` | 在模拟器上构建和测试 iOS 应用 | 给开发者构建、画面、日志和仍需人工核对的事项 |
| 二 | `spec-worktree` | 内部辅助：为获授权的调用方隔离 Git 工作树 | 给执行方独立工作位置及其身份 |
| 二 | `spec-commit` | 内部辅助：按调用方已有提交授权提交限定变更 | 返回本次提交；不负责推送或创建 PR |
| 二 | `spec-commit-push-pr` | 内部辅助：按已有交付授权提交、推送并创建或更新 PR | 给调用方提交和 PR 结果 |
| 二 | `spec-lfg` | 用户明确选择时，从规划推进到 PR 和 CI 检查 | 给交付负责人 PR、检查状态及未解决事项 |
| 二 | `spec-resolve-pr-feedback` | 处理 PR 上已有的评审意见 | 给 PR 作者各条意见的处置结果，不是重新发起代码评审 |
| 二 | `spec-handoff` | 跨会话移交工作，或按选定记录恢复 | 给接手者已完成项、证据、限制和恢复入口 |
| 二 | `spec-compound` | 将刚解决的问题提炼为可复用经验 | 给后续团队 `docs/solutions/` 中的经验记录 |
| 三 | `spec-strategy` | 明确产品方向，为后续选题与规划提供上游依据 | 给产品负责人 `STRATEGY.md` |
| 三 | `spec-product-pulse` | 汇总特定时间窗口中的产品信号 | 给负责人阶段性产品报告 |
| 三 | `spec-sweep` | 从已配置来源归集反馈、核对处理进展 | 给跟进方反馈处置结果及可接续的计划 |
| 三 | `spec-riffrec-feedback-analysis` | 解读明确指定的 Riffrec 产品反馈录制 | 给产品或研发与录制证据对应的反馈分析 |
| 三 | `spec-promote` | 依据实际交付证据撰写发布或推广文案 | 给传播负责人可审阅的草稿，不证明已对外发布 |
| 三 | `spec-runtime-setup` | 安装、配置、验证或刷新宿主工作环境 | 给维护者环境可用性事实与限制 |
| 三 | `spec-compound-refresh` | 按当前源码检查知识库中过期、重叠或失效的经验 | 给维护者更新后的经验与概念词表 |
| 三 | `spec-explain` | 把概念、差异或一段工作讲清楚 | 给学习者可持久阅读的可视化讲解，可附自测 |
| 三 | `spec-write-skill` | 创建、修改、迁移项目 Skill，或只读检查指定包 | 给维护者 Skill 源包或就绪报告，不直接修运行时镜像 |
