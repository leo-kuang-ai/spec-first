## 高价值缺陷及最小改法

按可能影响的决定排序；此处均为审阅建议，没有实施。

1. **只读范围错误未在读取前停止（源码确认）。** `scripts/validate-skill.cjs:181` 检测到目标不在授权根内或根不可用后仍继续，`scripts/validate-skill.cjs:357` 和 `scripts/validate-skill.cjs:367` 仍可能进入库存或正文读取。最终报错不能代替访问前拒绝。最小改法：授权根前置校验未通过即返回空库存，区分已知越界的 `fail` 和根不可核实的 `incomplete`；用读取调用计数验证未触达包内容，不以仅检查退出码代替。未对真实受限路径做探测。
2. **同一脏文件可以同时“保留”和“替换”（实测）。** `scripts/validate-authoring-preview.cjs:268` 可接受两种处置，却不检查其与 `would_change` 的对应关系。最小改法：计划重写的脏文件必须匹配明确的 `replace`；决定保留时，应移出写集，互相矛盾则不生成绑定。保留“明确同意替换”的正例。这是写前阻断，不能交给事后哈希补救。
3. **暂存包没有技能入口仍标目标就绪（实测）。** `scripts/inspect-context.cjs:43` 验的是两个集合相等，不能由此推出是一个技能包。最小改法：在报告 `ready` 前要求实际清单与声明都含根下普通文件 `SKILL.md`，继续校验其源哈希；复用基础校验时要针对**实际暂存包**，不是开发目录。保留完整包、空包、只有说明文件和漏报文件四个对照。
4. **唯一镜像行为 smoke 会把反例判为成功（实测）。** `evals/fixtures/scripts/check-mirror-refused.sh:9` 的词命中不区分“拒绝了”与“已经做了”。最小改法：在可写临时仓库预置独立源文件和镜像，以前后文件状态与写入尝试记录判“不改”；另判回答是否给出正确源路径和下一步。保留本报告的反向答复作判题器负例。缺动作证据时只报告“答复方向”，不宣称验证了克制。
5. **合法文档被只读检查判坏（实测）。** `scripts/validate-skill.cjs:78` 将整段引号值按 JSON 字符串处理，没有区分 YAML 行尾注释。最小改法：对这个可识别结构正确消费注释，或保守返回 `frontmatter_subset_unsupported`；用引号内的 `#`、引号后的注释及真正损坏的输入区分可判和不可判，保留退出码意义。
6. **小修重排没有唯一的必读说明（源码确认）。** `SKILL.md:52` 与 `references/evaluation-design.md:3` 写 Tier A 不读，`references/authoring-workbench.md:27` 却要求即使行为等价的重排也读重排小节。最小改法：入口只分“纯文字小修”和“涉及搬移的等价重排”，后者链接到对应小节，不强加完整设计记录；把预览命令旁的最小有效输入和回执失败示例放在工作台一处，不再复制授权长段。
