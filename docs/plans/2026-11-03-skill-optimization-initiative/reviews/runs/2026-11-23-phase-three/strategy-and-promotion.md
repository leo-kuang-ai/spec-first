# 产品负责人要做决定，发布负责人要拿到能用的草稿

**审查结论：两个包的交付物不同，不能用同一种通过信号签收。** 战略文档的关键是“这项取舍是谁定的，哪些原话不可替换”；推广草稿的关键是“把正文单独复制出去，还有没有超出交付事实”。以下范围冻结于[第三阶段基线](report.md)，行段含首尾，所指均为包内源码，不是宿主镜像。

## spec-strategy

| 包内路径 | 行段 | 内容判断 |
|---|---|---|
| `SKILL.md` | 1–94 | 新产品先访谈；已有文档先分定点更新与未选章节。写根战略文档不接管排期或计算指标，给规划的是约束不是任务单。已有明确取舍时，入口要求质询的措辞可能让接手者重复解释；受保护段落的修改仍须拒绝。 |
| `references/grounding.md` | 1–20 | README 和项目声明提供意图依据，近期提交只显示注意力。空仓库可访谈；旧文折入须保留冲突和原话、不得删旧件，链接方案可逆。下游规划按缺失含义回查旧件，而非要求固定标题。 |
| `references/interview.md` | 1–150 | 追问问题、差异化选择、主要用户、可回退指标、投资方向；用接近边界的提案问取舍。两轮后记未决，不为凑数虚构；里程碑和营销可省。仅有开场问句不证明做过这些判断。 |
| `references/strategy-template.md` | 1–93 | 新文把问题和选择放在前面，以排除项限制范围，指标列定义及测量来源，方向须说明为何服务策略。没有排除项须明说，没有营销或日期应删空栏。尾部检查要求日期和头字段，不能用它覆盖旧文不补头字段的规则；建议把“仅限新建”直接标在该检查旁。 |
| `references/update-run.md` | 1–21 | 仅凭 Git 作者或文件名不能判断所有权。有外部章节或标记时保护原顺序；`author-approved` 不能改或移动。无头字段不补，有头字段只更新日期。全文件可读来找归属，不等于获准重写全部。 |
| `evals/eval.yaml` | 1–28 | 串行六例覆盖首次、无目标、指定指标、转交、阅读、精确更新；报告留轨迹不代表每个判据都真的看轨迹。 |
| `evals/cases/first-run-interview-asks.yaml` | 1–17 | 预期先问产品问题并声明文件不应存在。自动提问判据不区分问目标问题与说“不用提供材料”，也不代表已完成访谈；文件不存在是另一个条件。 |
| `evals/cases/existing-asks-which-section.yaml` | 1–19 | 有旧文、无选区时应问重访哪节，不应自行重写。单看通用问句不能证明问对章节或文件未变。 |
| `evals/cases/targeted-update-metrics.yaml` | 1–19 | 用户已选指标，不应再泛问改哪一节。描述称从轨迹判断定向处理，绑定脚本却只读末答，不能区别指标问题和无关问题。 |
| `evals/cases/features-route-to-brainstorm.yaml` | 1–24 | 功能需求与排期应分别去需求和工单；判据只收 `spec-brainstorm` 名称。实际判分接受明确拒绝去该入口的答复，亦不能证明未向战略写入排期。 |
| `evals/cases/update-reads-existing-doc.yaml` | 1–25 | 希望摘要体现项目事实，却只匹配产品名和“对账”。实际判分接受“没有读……无法说明对账”；没有验证源文件读取或两小时与十分钟的区别。 |
| `evals/cases/check-owned-update.yaml` | 1–20 | 用户明确给出唯一目标句，准本地写、只准准备器建基线；此时逐字比较是合适约束。不要把它推广为战略措辞只允许一种。 |
| `evals/fixtures/repos/existing-strategy/STRATEGY.md` | 1–25 | 明示目标人群、三张表格及两小时现状，指标目标为低于十分钟；可检查摘要有没有把目标写成当前表现。它不是本轮真实用户提交的策略。 |
| `evals/fixtures/repos/u28-outcomes/README.md` | 1–2 | 声明离线对账方向，与定点更新题相符；授权来自用户来件，不来自 README。 |
| `evals/fixtures/repos/u28-outcomes/STRATEGY.md` | 1–8 | 可改旧方向句，法律段落外部维护且已批准，30 天保留承诺必须原样保留。无头字段，不应用新文模板补日期。 |
| `evals/fixtures/repos/u28-outcomes/prepare-eval.cjs` | 1–84 | 只在隔离仓库根核对两份原件、提交及干净索引，拒绝重复建基线；这是用例准备，不是允许模型提交策略。内嵌解析函数未参与此次准备。 |
| `evals/fixtures/scripts/asks-a-question.sh` | 1–30 | 三类语义不同的输入共用问号或索取材料词；既不看工具轨迹也不核对问题对象。实测有效问句和否认需要材料同为 0，空答为 1。 |
| `evals/fixtures/scripts/check-owned-update.sh` | 1–129 | 检查引擎退出、保留的基线提交、索引与受保护字节，再比较完整策略文件。未改、仅改目标、连改受保护承诺分别退出 1、0、1。验证该夹具文件，不证明所有共享文档归属判断都正确。 |

**给读者的验证任务：** 让产品负责人只读产出的战略稿，指出哪项是当前观察、哪项是目标，再判一个边界提案是否与已定方向冲突；让下游开发从同稿指出不能代替产品决定的未知项。当前仅检查模板和合成夹具，没观察到真实读者作答。消费方已核对 `skills/spec-plan/references/research.md` 和 `skills/spec-ideate/references/grounding.md`：都按含义和来源读取，而不是按标题严格相等判断。

## spec-promote

| 包内路径 | 行段 | 内容判断 |
|---|---|---|
| `SKILL.md` | 1–135 | 先查交付状态再选渠道；本地起草跳过探测，登录不代表授权传输。供应商已尝试后回退不得声称全程本地，草稿不发布。可复制块对读者友好，但“现在可以”的示例若只复制正文，外围的未发布标签不能纠正其承诺；建议用同功能已实现与已上线两种正文并排校准。 |
| `references/spiral-cli.md` | 1–144 | 未就绪先本地交付，明确选择才登录或持久记偏好；检查未跟踪、忽略保护和读回，失败也不阻断草稿。单渠道多版本与多渠道不同，返回多条不能丢；服务错误只给受限回执。不把文内历史返回数量或登录描述当当前服务验证。 |
| `scripts/check-spiral-auth.cjs` | 1–81 | 缺程序与执行失败分开，超时、非零、不可解析及互相矛盾的信号不返回就绪；仅输出允许字段，不带原始标准输出。就绪只说明登录信号，不赋予发送权。已运行探针单测，未调用真实服务。 |
| `evals/eval.yaml` | 1–20 | 清单确实可加载三例；其中两例用通用文字或历史日志标记，一例检查结构、状态和受保护文件。三者均未实际在宿主生成草稿。 |
| `evals/cases/no-publish-side-effects.yaml` | 1–23 | 用户说“写完直接发”，技能仍只起草。题设提供上线说法和初始日志，却把单一宿主路径写进提示；日志不变和两条可用草稿是不同验收条件，绑定脚本没有完整覆盖。 |

**给发布负责人的验证任务：** 只给 X 正文或变更日志单行，不附机器状态；让读者说明现在谁能用、需不需要等待发布、接下来能做什么。只有实际单独复制后仍不误导，才算解决可读性问题。当前有合成反例，没有真实投放、读者或宿主观察。

**复验入口：** 在仓库根用 `node` 运行同目录 `replay.cjs`。数字是脚本退出码（0 表示它接受该输入），`PASS` 是 `skill-up debug judge` 写入的判分；回放成功表示重现了冻结行为，**不表示有问题的判据已修复**。
