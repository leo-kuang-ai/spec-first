| 原问题 | 改后行为与复核依据 |
|---|---|
| 未知 PR 状态被当成已经关闭 | 快照入口仅接收开放、关闭或合并；保留原有大小写兼容。未知、空值、数组均拒收，不推进此前日志代次。见 `tests/unit/spec-lfg-pr-watch-state.test.js`；不需要真实 PR 即可核对脚本终态。 |

| 知识发布判据只查字段名与源码词，缺证据也能通过 | 使用正式晋升校验器、核对唯一文档和原始 `solved-ledger` 源码字节。缺工具或参照夹具不能签收；有文档不代表整次发布可信。见 `tests/unit/spec-compound-frontmatter-validation.test.js`。仅验证模拟发布判据，不证明线上发布、经验因果或未来复用效果。 |
| 浏览器默认入口丢样式，预览可能选错应用 | 子目录页面以同源、分段编码的实际 URL 打开，不放宽 `base-uri 'none'`；根单页保持原行为。Chrome 真实计算样式：默认和显式入口由 `missing/loaded` 变为 `loaded/loaded`。Astro 只吸收同目录 Vite 信号；Next 与 Astro 并存提示多应用，其他子目录的独立 Vite 保留。启动配置名称及 Rails 端口说明与读取器对齐。 |
| 配对实验保留决策与排名使用不同基线 | 同一目标的阈值、增量、排名和提前停止都使用实际配对的基线。固定两对 `10 → 16` 后，追加未配对的高值或低值，结果仍是 `keep / +6 / 0.6`；反向目标同验。没有降低配对或确认样本量。配置指引使用 `measurement.calibration.mode`，收尾示例先写实际保留版本和确认范围。 |
| 只测一个资源指标却没有列出未测的硬性维度 | 计分器分列有可比较基线的硬性维度及未评估维度；仅有资源观测会列出四个未评估项。保留原计分、最后一行状态及退出码，不能据此发布。见 `tests/unit/autoresearch-score-regression.test.js`。 |
| 本地提交成功就被解释成没有远端操作 | 用例仍验提交范围、索引及内容，但没有轨迹或轨迹为空就不能签收；有记录时仅报告“提供的轨迹未见可识别的远端写入”，不保证轨迹完整。校准覆盖空、缺、记录本地提交和含模拟远端写入四种情况，见 `tests/unit/sup-judge-hardening.test.js`。 |
| 含糊交接也可声称工作已完成 | 仅给这一份夹具指定结构化回答：选定来源、已验证变更、是否知道下一任务。无据填写分页已完成或声称下一步已知会失败；原有文件及 Git 状态不变检查保留。不把该格式强加给真实用户，也不把通过当作自由文本可读性证据。 |
| 未测流程写在“已测”下，摘要看不出能否放行 | 验收模板首屏显示版本、已执行数、套件结果和首要阻断，初稿行明确待测；浏览器报告分开范围与实际执行数。工作树说明不再把当前目录当作主检出。这里确认的是模板及操作说明，未做独立读者试读。 |
