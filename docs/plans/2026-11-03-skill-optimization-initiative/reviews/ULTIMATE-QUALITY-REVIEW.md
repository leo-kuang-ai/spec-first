### 框架 4：验收标准

#### 当前状态分析

**当前验收标准**（core/00-goals-and-success-criteria.md）：
```yaml
Layer 3（端到端）:
  - 端到端正确率 >90%
  - 端到端返工率 <10%
  - 用户介入次数 <3 次/任务

Phase 0 成功标准:
  - 完成 11 个任务追踪
  - 识别出明确的高频问题（≥60%）
  - 归因清晰（4 类根因）
  - 给出数据驱动的建议
```

#### 最佳实践对标

**最佳实践要求**：
```
"专业、深入、高质量、全面"表达期待，但不足以让 AI 判断何时完成。

应该改为可验证的标准：
- 深入调研 → 核验关键原始来源；覆盖主要方案、反例和适用条件
- 修好问题 → 原始复现通过；相关正常路径无回归
```

| 维度 | 要求 | 当前方案 | 评分 |
|---|---|---|---|
| **正确性验证** | 可机械判定 | ✅ 量化指标（>90%, <10%） | 10/10 |
| **完整性验证** | 可机械判定 | ✅ 11 个任务，≥60% 模式 | 10/10 |
| **可用性验证** | 可机械判定 | ⚠️ "数据驱动的建议"定义模糊 | 7/10 |
| **外部证据** | 要求 | ⚠️ 部分验收依赖主观判断 | 7/10 |

**评分**：8.5/10 ✅

**优点**：
- 核心指标量化（>90%, <10%, <3 次）
- 完整性可验证（11 个任务）
- 有 DECISION-RULES.md 量化所有阈值

**发现的问题**：
1. **"数据驱动的建议"定义模糊**（-3 分）
   - 问题：什么算"数据驱动"？
   - 当前：没有明确标准
   - 影响：执行者不确定是否完成

2. **部分验收依赖主观判断**（-3 分）
   - 问题："明确的高频问题"如何判断？
   - 当前：≥60% 重复率
   - 但："是否明确"仍有主观性

**建议改进**（P0，1 小时）：
```yaml
补充验收清单（具体可检查）:

Phase 0 报告合格标准:
  正确性:
    - [ ] 每个基线数字可追溯到原始 YAML
    - [ ] 归因分类使用 4 类定义（Skill/模型/外部/工具）
    - [ ] 计算公式明确（如：返工率 = X/11）
  
  完整性:
    - [ ] 11 个任务全部追踪
    - [ ] 每个任务包含所有必需字段（见模板）
    - [ ] 发现的问题在 ≥60% 任务中重复出现
  
  可用性:
    - [ ] 报告包含"决策建议"章节
    - [ ] 建议明确属于 4 种退出条件之一
    - [ ] 如果建议启动 Phase 1:
      - [ ] 列出 2-3 个需优化的 Skill
      - [ ] 每个 Skill 有具体问题描述
      - [ ] 预估投入和预期改善
  
  数据驱动:
    - [ ] 每个建议都引用具体数据（任务 ID + 行号）
    - [ ] 归因占比 ≥50%（如果建议优化 Skill）
    - [ ] ROI >1（如果建议启动 Phase 1）

自动检查脚本（可选）:
  python scripts/validate-phase0-report.py report.md
  → 检查必需章节、数据引用、计算正确性
```
