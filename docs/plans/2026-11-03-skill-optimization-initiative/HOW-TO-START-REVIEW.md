# 如何开始审查 - 启动指南

**适用对象**：项目审查者、决策者、技术负责人  
**阅读时间**：5 分钟  
**目的**：提供清晰的审查启动路径

---

## 🎯 审查目标

判断这个 Skill 优化项目方案是否：
1. **合理**：方法论是否科学
2. **可行**：能否实际执行
3. **值得**：投入产出比是否合理
4. **可信**：结论是否有依据

---

## 🚀 三种审查路径

### 路径 1：快速审查（30 分钟）⚡

**适合**：决策者、需要快速了解的人

**阅读顺序**：
1. **README.md**（5 分钟）
   - 项目概述
   - 目录结构
   - 当前状态

2. **core/00-goals-and-success-criteria.md**（10 分钟）
   - 项目目标（已修正：不预设必须优化）
   - Phase 0 三大问题
   - 4 种退出条件

3. **reviews/README.md**（10 分钟）
   - 8 轮审查时间线
   - 核心结论（方法论 9.6/10，整体 8.3/10）
   - 关键建议（移除假设收益，Phase 0 确定基线）

4. **reviews/corrections/corrections-summary.md**（5 分钟）
   - 发现的问题（收益估算基于假设）
   - 修正方案（3 项核心修正）
   - 修正效果（7.4/10 → 8.3/10）

**审查结论**：
- ✅ 如果认可"数据驱动决策" → 可以启动 Phase -1 试点
- ⚠️ 如果对方法论有疑问 → 进入路径 2 深度审查
- ❌ 如果不认可投入 → 项目暂停

---

### 路径 2：深度审查（2 小时）🔍

**适合**：技术负责人、架构师、需要深入理解的人

**阅读顺序**：

#### 第一步：理解方法论（30 分钟）

1. **core/01-v4-workflow-driven-approach.md**
   - v4 方法论（研发流程导向）
   - 三层标准（Layer 3 > Layer 2 > Layer 1）
   - 为什么不是 v1/v2/v3

2. **reviews/04-harness-expert-review.md**
   - Harness 最佳实践对标
   - 契合度 9.6/10（核心理念）
   - 缺失的实践（Contract、Protocol）

**审查点**：
- [ ] 方法论是否科学？
- [ ] Harness 最佳实践是否契合？
- [ ] 三层标准是否合理？

---

#### 第二步：评估可行性（30 分钟）

1. **core/08-skill-contract-protocol.md**
   - 5 个 Skill 的 Contract 定义
   - 3 个 Protocol 定义
   - 自动检查逻辑

2. **core/09-implementation-roadmap.md**
   - Phase -1 试点（4h）
   - Phase 0 计划（44h）
   - Phase 1 计划（78-140h）

**审查点**：
- [ ] Contract/Protocol 定义是否清晰？
- [ ] Phase 0 是否可执行？
- [ ] 时间估算是否合理？

---

#### 第三步：批判性思考（30 分钟）

1. **reviews/corrections/conclusion-analysis.md**
   - 10 个维度的批判性分析
   - 5 个关键质疑
   - 必须修正的问题

2. **reviews/05-completeness-review.md**
   - 发现的 8 个缺失项
   - P0/P1/P2 分级
   - 补充建议

**审查点**：
- [ ] 批判性分析是否合理？
- [ ] 发现的问题是否已修正？
- [ ] 还有哪些风险未考虑？

---

#### 第四步：投入产出评估（30 分钟）

**投入**：
- Phase -1：4 小时（试点验证）
- Phase 0：44 小时（数据收集）
- Phase 1：78-140 小时（优化实施，基于 Phase 0 决定）
- 总计：92-184 小时（分阶段投入，可随时止损）

**产出**（修正后，不承诺绝对数字）：
- Phase 0：确定真实基线 + 数据驱动决策
- 如果 Phase 0 发现不需要优化 → 这也是成功
- 如果需要优化 → 相对基线改善 ≥30%

**审查点**：
- [ ] 投入是否可接受？
- [ ] 产出是否有价值？
- [ ] 风险是否可控？

---

### 路径 3：专家级审查（4+ 小时）🎓

**适合**：需要完全理解方案的专家

**阅读顺序**：
1. 按 core/README.md 的推荐顺序读完所有核心文档（4 小时）
2. 读完所有审查报告（reviews/ 目录，2 小时）
3. 查看证据文件（evidence/ 目录，1 小时）
4. 自己做批判性分析（2 小时）

**审查清单**：
- [ ] 方法论完整性
- [ ] 执行可行性
- [ ] 收益可信度（已修正）
- [ ] 风险覆盖度
- [ ] 文档质量
- [ ] 组织可行性
- [ ] 与业界最佳实践对比
- [ ] 长期可维护性

---

## 📋 审查检查清单

### 方法论层面

- [ ] **v4 方法论是否合理？**
  - 研发流程导向 vs 单纯优化 Skill
  - 三层标准（端到端 > 阶段衔接 > 单个 Skill）
  - 数据驱动 vs 主观判断

- [ ] **Harness 最佳实践是否契合？**
  - "Gate the exits, not the thinking"
  - 验证门设计
  - Contract/Protocol 机制

- [ ] **Phase 0 目标是否明确？**（关键修正点）
  - ✅ 目标 1：确定真实基线（最重要）
  - ✅ 目标 2：判断是否需要优化
  - ✅ 目标 3：如果需要，优化什么
  - ❌ 不是"优化到 90% 正确率"

---

### 执行层面

- [ ] **Phase -1 试点是否必要？**
  - 4 小时验证追踪方法
  - 降低 Phase 0 的风险
  - 可行性评估

- [ ] **Phase 0 是否可执行？**
  - 11 个任务追踪（前瞻性 + 回顾性）
  - Contract/Protocol 检查
  - 4 类根因归因
  - 44 小时时间估算

- [ ] **Phase 1 是否有清晰的决策机制？**
  - 基于 Phase 0 数据决定
  - 4 种退出条件明确
  - 止损条件清晰

---

### 收益层面（关键修正点）

- [ ] **收益估算是否诚实？**（已修正）
  - ❌ 不承诺"返工率 73% → 10%"（基线未知）
  - ✅ 承诺"Phase 0 确定基线"
  - ✅ 承诺"相对基线改善 ≥30%"（如果执行 Phase 1）

- [ ] **"不需要优化"是否被认可为成功？**（关键）
  - Phase 0 发现质量已达标 → 项目成功完成
  - Phase 0 发现问题不在 Skill → 调整方向
  - 数据驱动决策 > 预设必须优化

---

### 风险层面

- [ ] **主要风险是否已识别？**
  - Phase 0 数据质量不足（Phase -1 缓解）
  - 11 个任务样本量不足（动态调整）
  - Phase 1 效果不达预期（止损条件）
  - 归因错误（4 类归因 + 验证）

- [ ] **假设风险是否已处理？**（关键修正点）
  - ✅ 基线假设已移除
  - ✅ 收益假设已修正
  - ✅ Phase 0 目标已明确

- [ ] **组织风险是否考虑？**
  - 资源可用性（谁来执行？）
  - 决策权限（谁批准 Phase 1？）
  - 变更管理（如何推广优化后的 Skill？）

---

## 🎯 审查决策框架

### 决策 1：是否启动 Phase -1 试点？（4 小时）

**条件**：
- [ ] 认可"数据驱动决策"原则
- [ ] 有 4 小时时间验证方法
- [ ] 愿意基于试点结果决定是否继续

**建议**：✅ 启动（风险低，收益高）

---

### 决策 2：Phase -1 后，是否启动 Phase 0？（44 小时）

**条件**（Phase -1 结果）：
- [ ] 追踪方法可行（数据质量好）
- [ ] 认可 44 小时投入
- [ ] 理解 Phase 0 的真正目标是"确定基线"

**决策**：
- ✅ 可行 → 启动 Phase 0
- ❌ 不可行 → 调整方法或暂停

---

### 决策 3：Phase 0 后，是否启动 Phase 1？（78-140 小时）

**条件**（Phase 0 结果）：
- [ ] 基线已确定
- [ ] 发现明确问题（归因为 Skill 问题）
- [ ] 预期改善 ≥30%
- [ ] 投入 < 预期收益

**决策**（4 种退出条件）：
1. 质量已达标 → 项目成功完成（不执行 Phase 1）
2. 需要优化 Skill → 启动 Phase 1
3. 问题不在 Skill → 调整方向（不执行 Skill 优化）
4. 成本 > 收益 → 暂停项目

## ✅ 快速决策（1 分钟）

如果你只有 1 分钟，回答这 3 个问题：

1. **是否认可"数据驱动决策"原则？**
   - ✅ 认可 → 继续
   - ❌ 不认可 → 项目不适合

2. **是否愿意投入 4 小时验证方法？**
   - ✅ 愿意 → 启动 Phase -1
   - ❌ 不愿意 → 项目暂停

3. **是否接受"不需要优化也是成功"？**
   - ✅ 接受 → 目标明确
   - ❌ 不接受 → 重新定义目标

如果 3 个都是 ✅ → **可以启动**
