## 详细分析

### Skill 1: spec-plan

#### Phase 0 发现

- M2 模式（首轮产出需兜底轮）主载体：4/9 任务方案层需至少一轮修订（T01/T06/T10 + T03 judge 类比）
- 具体问题：Implementation Commands 漏单元命令（T01）、聚焦验证盲区致 2 断言回归（T01）、语义筛查/准入合同缺失（T10）、doc-review 加固成常态（T06）

#### 深度解读发现

- **根本原因**：门1 自审清单（35+ 项）为内容质量范式，无跨集合一致性（对账）范式；单元级 outcome 表述与计划级命令分离（structure.md:104,199）且无对账义务；既有合同测试发现义务仅存在于 interface 镜头一处（条件触发）。集合对账机械可判定，恰属「scripts enforce deterministic invariants」应由合同强制、当前留给模型自觉的部分——这正是「不稳定」的机制：模型状态好则想到、差则漏，由更贵的兜底层捕获。
- **归因修正**：见分析报告 Step 3 逐项验证（1 ❌修正 / 3 ⚠️精确定位或调整 / 1 范围外维持）

#### 优化方案

- 方案 A+B（推荐）：final-review.md 5.1 增 2 条对账检查 + plan-sections.md Verification Contract 增触碰面合同测试声明与盲区句义务 + 合同测试同步 + 2 个 eval 案例
- 投入：4h ｜ 预期效果：M2 可上游预防类缺陷出现率下降 ≥50%（5 任务增量追踪验收）
- 完整设计、风险与验证方法：[phase05-analysis/skill-1-analysis.md](phase05-analysis/skill-1-analysis.md)
