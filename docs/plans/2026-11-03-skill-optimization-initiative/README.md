## 🎯 研发流程全景

### 一个真实需求如何走完

```
1. 项目理解与环境准备
2. 方向与需求定义
3. 方案与任务拆分
4. 实施与问题处理
5. 质量验证
6. 提交与反馈闭环
7. 恢复与知识复用
8. 跨阶段协调
```

### 三个分析层面

| 层面 | 检查内容 | 评估方法 |
|---|---|---|
| **Layer 1** | 单个 Skill 是否有效 | 指令清晰？过时约束？不必要工作？ |
| **Layer 2** | 阶段之间是否衔接顺畅 | 信息丢失？信息重复？验证缺失？ |
| **Layer 3** | 整个任务是否真正完成 | 端到端正确率？返工率？用户介入？ |

## ✅ 成功标准（调整）

### 不再是单个 Skill 指标

### Layer 3：端到端交付质量（最重要）

- **端到端正确率 >90%**：完全正确的任务数 / 总任务数
- **端到端返工率 <10%**：需要返工的任务数 / 总任务数
- **用户介入次数 <3 次/任务**：平均每任务的澄清、确认、修正次数

### Layer 2：阶段衔接顺畅度

- 信息丢失率 <5%：上游已确定但下游未使用
- 信息重复率 <10%：下游重复询问上游已确定信息
- 验收条件落实率 >90%：Work 实现的验收条件数 / Plan 中的验收条件数

### Layer 1：单个 Skill 有效性

- 指令清晰度：无歧义、无矛盾
- 必要性：不做不必要的工作
- 完整性：无遗漏检查

### Layer 3：整体交付质量（最重要）

- 端到端正确率：>90%
- 端到端返工率：<10%
- 用户介入次数：<3 次/任务
- 端到端完成时间：基线 -20%
