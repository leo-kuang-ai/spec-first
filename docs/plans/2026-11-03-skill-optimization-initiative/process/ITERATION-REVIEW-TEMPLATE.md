# Skill 审查报告模板

模板版本：v2.0 · 更新日期：2026-11-04

按 [Skill 审查 Workflow](REVIEW-EXECUTION-WORKFLOW.md) 填写。用于新审查或阶段复验；不是预填完成报告。复制到本轮 `reviews/runs/<日期>-<主题>/report.md` 后填写，所有占位内容均需替换；必要项缺失时保留缺口，不删除来换取完成。引用必须改为相对新报告的有效路径，或明确 repo-relative 路径。

## 1. 结论与本轮身份

- 审查类型、目标与范围：待填写。
- 审查执行：待判定（`complete` / `partial` / `blocked`）。
- 被审对象：待判定（通过 / 有条件通过 / 不通过 / 证据不足）。
- 收益结论：待判定（已验证 / 未验证 / 不适用）。
- 核心发现、阻断项、限制：待填写。
- target_repo、日期、owner、审查者：待填写。
- Git HEAD、dirty 基线与保护方式：待填写。
- 当前有效合同、采用指标与阈值、来源冲突及处置：待填写。
- 承诺检查与必需场景、范围外对象及理由：待填写。
- 当前授权、调用/费用预算、实际使用、停止条件、恢复点：待填写。
- 实际宿主/模型/工具配置、加载方式：待填写；未知不能靠名称推断。
- 复核方式与独立性：待填写；inline 多视角不得记独立复核。
- 试点后规模估算：待填写（单位成本、分组外推、假设与误差、与预算比较）；收缩选项及 owner 确认记录，未收缩写“无”。

## 5. 交接与场景

H01–H05、ML-01–ML-07 逐项记录；链外消费者追加实际边。不适用说明理由，不得批量写“全通过”。

| ID | 生产者/消费者或场景 | 适用性 | 承诺验证与源码版本 | 实际证据层及证据 ID | 结果、缺口 |
|---|---|---|---|---|---|
| 待填写 | 待填写 | 待填写 | 待填写 | 待填写 | 待判定 |

每次运行记录：

- 场景/尝试 ID、输入与 fixture 身份、覆盖检查项、运行前判据与禁止行为。
- 实际模型/宿主/工具/加载方式、隔离情况、基线/候选身份；oracle 与被测输入的隔离。
- 基线 SHA 与候选 SHA（或工作区字节），以及每个被注入文件的 SHA-256；只有候选侧时写明，收益结论记未验证。
- 任务清单与判据的固定时间或 commit、选择者（实施者本人/他人/规则生成）、结果出现后的增删替换及理由；判定是否盲评。
- 工作目录、命令/参数、开始结束时间、exit code、原始日志/轨迹、实际产物、判定依据。
- 首轮与最终结果、失败/重试、有效/无效及排除原因、成本与局限。
- 未执行部分及原因；配置或 source 改变后哪些证据失效。

## 8. 收尾与恢复

- workflow 第 9 节逐项验收结果：待填写。
- 阻断项与最小补齐动作：待填写。
- 非阻断残余、接受者及真实授权来源：待填写；不能以模型自填签字冒充人工批准。
- 未运行/不可复核/未覆盖范围及结论影响：待填写。
- 本轮实际修改与外部副作用：待填写；纯审查应区分证据产物和被审源码修改。
- 后续保持/修复/补证/调整方向及 owner：待填写。
- 恢复点、证据访问位置、失效与重评条件：待填写。

本报告描述当前证据；提交、发布、runtime 生效和真实收益分别判断，不由“审查完成”推导。
