# 审查执行 Workflow 文档

**文档版本**：v1.0  
**创建日期**：2026-11-03  
**目的**：提供清晰的审查执行流程，确保任何人都能高质量地审查本方案  
**适用对象**：审查者、决策者、第三方评估人员

---

## 🎯 Workflow 概述

本文档提供 3 种审查路径：
1. **快速决策审查**（30分钟）- 适合决策者
2. **标准质量审查**（2小时）- 适合技术负责人
3. **完整专家审查**（4-8小时）- 适合需要深度理解的专家

每种路径都有清晰的步骤、检查点和输出物。

## 🚀 路径 1：快速决策审查（30分钟）

**适用场景**：
- 决策者需要快速判断是否值得投入
- 关注点：可行性、ROI、风险

**时间分配**：
- 阅读：20 分钟
- 记录和决策：10 分钟

---

### Step 1：阅读项目概述（5分钟）

**阅读文档**：
1. `README.md`（3分钟）
2. `HOW-TO-START-REVIEW.md` - 快速决策部分（2分钟）

**检查点**：
- [ ] 理解项目目标（评估质量 + 数据驱动决策）
- [ ] 理解三个阶段（Phase -1/0/1）
- [ ] 理解成功定义（"不需要优化"也是成功）

**关键问题**：
```
Q1: 项目目标是否清晰？
Q2: 为什么要做这个项目？
Q3: 不做会有什么问题？
```

**记录发现**：
```markdown
## Step 1 发现
- 目标：[清晰/模糊/其他]
- 理由：[充分/不充分/其他]
- 疑问：[列出疑问]
```

---

### Step 2：评估投入产出（10分钟）

**阅读文档**：
1. `core/00-goals-and-success-criteria.md` - 目标和标准（5分钟）
2. `core/09-implementation-roadmap.md` - 投入估算部分（5分钟）

**投入分析**：
```yaml
Phase -1 试点: 4 小时
Phase 0 数据收集: 44 小时
Phase 1 优化（条件性）: 78-140 小时

总投入:
  - 最小: 48 小时（Phase -1 + 0）
  - 标准: 92 小时（+ Phase 1 最小）
  - 最大: 188 小时（+ Phase 1 最大）
```

**产出分析**：
```yaml
Phase 0 产出:
  - 确定真实基线
  - 数据驱动的决策建议
  - 价值: 即使不启动 Phase 1，也有价值

Phase 1 产出（如果启动）:
  - 预期改善: 相对基线改善 ≥30%
  - ROI: >1
  - 价值: 长期提升研发效率
```

**检查点**：
- [ ] 投入是否可接受？（48-188小时）
- [ ] 产出是否有价值？（基线数据 + 改善）
- [ ] 分阶段投入机制是否合理？（可随时止损）

**关键问题**：
```
Q1: 48 小时（Phase 0）的投入是否可接受？
Q2: 如果 Phase 0 发现"不需要优化"，这 48 小时是否值得？
Q3: ROI >1 的预期是否可信？
```

**记录发现**：
```markdown
## Step 2 发现
- 投入：[可接受/过高/其他]
- 产出：[有价值/价值不明确/其他]
- ROI：[可信/不可信/其他]
- 疑问：[列出]
```

---

### Step 3：风险评估（10分钟）

**阅读文档**：
1. `reviews/GAP-TO-PERFECT.md` - 差距分析（5分钟）
2. `core/DECISION-AUTHORITY.md` - 决策权限（5分钟）

**风险清单**：
```yaml
组织风险:
  - 资源可用性: [评估]
  - 决策权限: [评估]
  - 团队接受度: [评估]

执行风险:
  - Phase 0 数据质量: [缓解措施]
  - 样本量不足: [缓解措施]
  - 方法可行性: [Phase -1 验证]

收益风险:
  - 基线假设: [不预设，Phase 0 确定]
  - 改善预期: [保守估计，数据支持]
  - ROI 计算: [基于实际数据]
```

**检查点**：
- [ ] 主要风险是否已识别？
- [ ] 每个风险是否有缓解措施？
- [ ] 止损机制是否清晰？

**关键问题**：
```
Q1: 最大的风险是什么？
Q2: 如果风险发生，损失有多大？
Q3: 止损条件是否明确？
```

**记录发现**：
```markdown
## Step 3 发现
- 主要风险：[列出 Top 3]
- 缓解措施：[充分/不充分]
- 止损机制：[清晰/不清晰]
- 疑问：[列出]
```

---

### Step 4：审查结论和决策（5分钟）

**综合评估**：
```yaml
3 个核心问题:
  Q1: 是否认可"数据驱动决策"原则？
    - [ ] 是 - 继续
    - [ ] 否 - 不适合

  Q2: 是否愿意投入 48 小时（Phase 0）验证？
    - [ ] 是 - 继续
    - [ ] 否 - 暂停

  Q3: 是否接受"不需要优化也是成功"？
    - [ ] 是 - 目标明确
    - [ ] 否 - 重新定义目标

如果 3 个都是"是" → 可以启动
```

**快速决策矩阵**：
```
情况 1: 3 个都是"是"
  → ✅ 批准启动 Phase -1（4小时试点）

情况 2: 2 个"是"，1 个"否"
  → ⚠️ 需要解决"否"的问题
  → 解决后再决策

情况 3: ≥2 个"否"
  → ❌ 不批准启动
  → 说明理由
```

**输出物**：
```markdown
## 快速决策审查结论

**审查者**：[姓名]
**日期**：[YYYY-MM-DD]
**耗时**：30 分钟

### 评估结果
- 目标清晰度：✅ / ⚠️ / ❌
- 投入产出比：✅ / ⚠️ / ❌
- 风险可控性：✅ / ⚠️ / ❌

### 3 个核心问题
- Q1（数据驱动）：是 / 否
- Q2（投入意愿）：是 / 否
- Q3（成功定义）：是 / 否

### 决策
- [ ] ✅ 批准启动 Phase -1
- [ ] ⚠️ 有条件批准（需要：___）
- [ ] ❌ 不批准（理由：___）

### 关键建议（如果有）
1. [建议 1]
2. [建议 2]

### 签字
审查者：[签名]
日期：[YYYY-MM-DD]
```
