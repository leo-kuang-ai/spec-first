## 结论

### 1. 方法论内核有效，且已被自身数据验证

v4 方法论（core/01：从真实任务出发、沿流程找阻力点、不预设 Skill 清单）的核心价值不在于预设了什么，而在于**它的止损与判定规则真的被执行了**：

- Phase 0 实测 9 个真实任务，归因结果为 skill 层仅占 32-37.5%（Phase 0.5 修正后口径），external/tooling/model 合计过半；
- 按 `core/DECISION-RULES` 规则 3 判定 2/5 条件满足 → 情况 4「不启动 Phase 1」；
- 该判定**否决了这套方案自己的主推进路线**。一套方法论用自己的测量规则否决自己的主计划，恰恰证明反预设设计在起作用，而非流于纸面。

### 2. 约半数事前设计诚实降级，属诚实记录而非失败

17 份事前设计中：5 份未执行/未采纳（已于 2026-11-04 归档至 `../archive/`），08 的 schema/自动检查器部分未采纳，09 偏离执行（11 周实际 2 天、无 A/B 对照）。core/README 以三层分类如实记录每份的实际角色，未把「机制设计了」伪装成「已兑现」。这符合仓库「诚实降级不是免责声明」的治理要求；但按同一要求，降级项的重估条件应随本轮 Option B 结果回填。

### 3. 核心张力：实际投入流向与自身决策规则相反

规则 3 判定「Skill 问题不是主要矛盾」，但实际投入（Phase 0.5 深读 8h/Skill + 6 项 Skill 优化）仍流向 Skill 层，由 owner override 启动且已记录。方法论正确识别了矛盾，组织选择仍按旧惯性行动——这是整套方案最值得外部采纳者注意的一条经验：**测量可以否决计划，否决能否生效取决于 owner 是否接受**。

### 4. Option B 的有效定位：取证批次，收益=未验证

Option B（v3.6，v2 主链路批次）成立的理由是**补齐审查证据**：覆盖 38%→100%（52 完全 + 1 范围外如实标注，v1.4口径）是审查覆盖账目，不是 Skill 质量改善结论。执行完成后，收益层结论（Skill 是否因此变好）仍需按 v2 三态完成标准单独验证，不得由覆盖闭合自动推导。
