**C2 · 数字层按想象校准，不可复用**（落地 P0#1 / 方法论 P1#5 / 落地 P1#6，3/4 命中）

**C5 · 测量层三缺陷**（方法论专家主挖，P0×3）
① 出口非 MECE：实测归因（skill 37.5%/external 28.6%）无任何类≥50%，落入退出 2 与退出 3 之间的未定义区，执行被迫选"退出 3"但其成文前提未满足；00:397 用 ≥50% 门槛 vs DR:431 外部 ≥20% 即可选✓——同一构念两套互斥阈值。② 阈值在噪声带宽内：n≈28 票下 37.5% 的 95%CI 约 ±18pp，"2/5 vs 3/5"（情况 4 vs 决策会议）之差在噪声内；达标线 00<10%✓ vs DR<15%✓ 在 10-15% 区间判定相反。③ 归因无信度设计：单评定者、无编码手册、半票任意分割✓（final-report:92 skill_issue 10.5 票）系统性稀释最大类别；按"原因位置"编码却用于"修复路径"选择——构念错位。

**C6 · 弃 schema 保 prose：方向正确、需补成文理由**（架构 P1#2 + AI P1#2，独立收敛）
08 的数量门校验的是 LLM 自报字段，是"给自我声明盖章的伪确定性"；弃 schema 保 prose 符合"scripts deterministic / LLM semantic"分工。但属事后追认：弃用理由未成文、复活条件缺失、08:577 仍自称"✅ 可执行"。唯一值得 schema 化补回的确定性面：R/AE ID → Plan U-ID 跨阶段引用对账。

## 三、关键分歧与负责人仲裁

**分歧：规则 3"情况 4"判定是否可靠。**
- 架构/落地/AI 三位：规则真实生效、自我证伪范本（事后证据：override 后返工 66.7% 未达标恰是规则预测的结局）。

**仲裁**：两者兼容且都成立——**方向判对，推理不健全**。结论恰好正确（override 兑现了规则预测的损失）不等于判定过程可靠，下次未必恰巧。处置：(a) DECISION-RULES 复用前必须先修 MECE 与阈值-样本匹配；(b) 本项目对外表述从"数据驱动"降为"数据辅助 + 事后验证"；(c) 该仲裁本身属负责人单方判断，advisory。

## 五、四份评审结论摘要（原始保留）

### 5.1 研究方法论专家：需修
治理骨架（预注册/退出条件/三层链/诚实降级）上乘，但测量层不成立——测量时点未定义、归因无信度、阈值在 n=9 噪声带宽内、四出口非完备划分；"情况 4"判定本身是规则歧义与小样本噪声的产物。8 项 findings（P0×3：出口非 MECE / 阈值跨文档冲突且对 n 不稳健 / 归因无信度且构念错位；P1×3：测量时点未定义 / 假设值洗白成基线 / 小样本下目标不可证伪；P2×2：抽样框配额整层脱落 / 治理角色虚构）。亮点：预注册并真实服从负结论、"不需要优化也是成功"进成功定义、执行侧报告文化优于测量设计。

### 5.2 架构与治理专家：需修
方法论骨架成立且已被 Phase 0 数据自证有效，但决策治理层存在已兑现为实际损失的缺口。8 项 findings（P0×1：override 无闭环；P1×4：08 弃 schema 属正确演化但理由未成文 / DR 把语义估计当 confirmed truth / RACI 治理角色虚构 / 规则覆盖止于 Phase 1 止损无"验证未达标后动作"；P2×3：06 freshness 风险 / 缺集成一致性 pass / handoff 冲突靠 README 仲裁而非修源）。亮点：06 是宪法级范本、"不预设"真兑现、README 三层分类可审计。

### 5.3 研发效能专家：需修
判断层被实测证明有效，但执行层设计整体按"多人纯人工团队"想象编写，实际靠系统性偏离原设计才兑现价值。8 项 findings（P0×2：估算体系按人类吞吐校准差 1-2 量级 / 12 深读法对准 Python 代码库且 8h≠分项 10h；P1×4：双 02 冗余冲突 / YAML 模板 0/9 使用格式漂移 / 资源治理无单人+AI 档 / ROI 建立在假设基线上；P2×2：06 基线无 owner / 07 三合一漂移）。亮点：量化闸门真实生效、"先测量再优化"拦下 112-204h 错误投入、06 证据纪律。

### 5.4 AI·Harness 工程专家：需修
判定层与基线层是罕见的预注册自我证伪范本，但三份实施设计（08/11/12）未读源码按想象架构开方，行为验证层至今零执行。7 项 findings（P0×1：实施设计不以源码为据；P1×3：弃 schema 方向正确但属事后追认 / 八维镜从未对准自己（D01/D05 直接指控现存 spec-prd 形态却未被用于本体判定）/ 12 无"LLM 审 LLM"盲区对策；P2×3：ML 场景零执行且无评分者协议 / D06-D08 优先级应互换 / 11 的 12 缺口中 3 条与源码矛盾、4 条被 git 或宿主商品化覆盖）。亮点：规则 3 真实触发并压制乐观计划、06 的评测诚实纪律、"LLM 语义判断+脚本 machine receipt"双轨解先于设计存在。
