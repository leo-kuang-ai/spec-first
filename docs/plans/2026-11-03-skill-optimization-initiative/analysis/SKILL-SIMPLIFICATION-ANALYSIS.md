## 🔍 深入分析：为什么要精简？

### 理由1：Token成本

**当前状况**（假设数据）：
```yaml
spec-prd调用一次:
  主文件: 8409词 ≈ 11,000 tokens
  如果80%是样板: 浪费 8,800 tokens/次
  
月调用100次: 浪费 880,000 tokens
年成本估算: $XXX
```

**精简后**：
```yaml
spec-prd调用一次:
  主文件spine: 2000词 ≈ 2,600 tokens
  按需references: 仅在需要时加载
  
节省: ~75% token成本
```

### 理由2：上下文效率

**长Skill的问题**：
- 80%内容在大多数调用中不需要
- 模型需要处理大量无关信息
- 降低关键信息的注意力权重

**精简后**：
- 模型只看核心流程
- 按需加载深度内容
- 关键信息更突出

### 理由3：维护性

**当前问题**：
- spec-prd：347行，8409词，难以快速定位
- 跨Skill重复样板（Runtime Context Exclusion出现在6个Skill）
- 样板修改需要同步多个文件

**精简后**：
- 主文件短小，易读易维护
- 样板集中在references/governance-boundaries.md
- 修改一次，所有Skill受益
