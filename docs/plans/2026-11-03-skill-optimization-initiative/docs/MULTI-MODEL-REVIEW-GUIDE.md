# 多模型审查指南 - 使用不同 AI 模型进行交叉验证

**日期**：2026-11-03  
**目的**：利用不同 AI 模型的视角进行交叉审查，提升方案可信度

---

## 🎯 为什么使用多模型审查？

### 优势

1. **消除单一模型偏见**
   - 每个模型有自己的训练数据和倾向
   - Claude 可能倾向于自己设计的方案
   - 其他模型提供独立视角

2. **发现盲点**
   - 不同模型关注点不同
   - GLM（智谱）可能更关注中文场景
   - GPT 可能更关注工程实践
   - Claude 可能更关注理论完整性

3. **提升可信度**
   - 多个模型都认可 → 方案可信度高
   - 发现分歧 → 需要深入思考
   - 交叉验证 → 降低风险

## 🔧 多模型审查方案

### 方案 1：交叉审查（推荐）⭐

**模型组合**：3 个不同模型

```yaml
审查分工：
  模型 1（Claude）：
    - 方法论完整性审查
    - Harness 最佳实践对标
    - 批判性分析
    原因：Claude 擅长逻辑和批判性思维
  
  模型 2（GPT-4）：
    - 执行可行性审查
    - 技术方案审查
    - 工程实践对标
    原因：GPT-4 擅长工程实践
  
  模型 3（GLM-5.3）：
    - 本土化审查
    - 可读性审查
    - 实施细节审查
    原因：GLM 更理解中文和国内场景
```

**执行步骤**：
1. 每个模型独立审查（不看其他模型结论）
2. 收集 3 份独立审查报告
3. 对比分析：
   - 一致的结论 → 高可信度
   - 分歧的地方 → 深入分析
4. 综合判断

**时间成本**：每个模型 2 小时 × 3 = 6 小时

---

### 方案 2：分层审查（效率优先）

**模型组合**：2 个模型

```yaml
第一层（快速筛查）- GLM-5.3：
  时间：30 分钟
  内容：
    - README.md
    - core/00-goals
    - reviews/README.md
  目标：快速判断是否值得深入
  
  决策点：
    - ✅ 值得深入 → 进入第二层
    - ❌ 不值得 → 给出理由，项目暂停

---

第二层（深度审查）- GPT-4 或 Claude：
  时间：2 小时
  内容：
    - 所有核心文档
    - 所有审查报告
    - 批判性分析
  目标：全面评估可行性和价值
```

**时间成本**：30 分钟 + 2 小时 = 2.5 小时

---

### 方案 3：专项审查（针对性）

**模型组合**：根据审查重点选择

```yaml
审查重点 1：方法论是否科学？
  → 使用 Claude（擅长逻辑和理论）
  
审查重点 2：能否在国内落地？
  → 使用 GLM-5.3 或文心一言（理解国内场景）
  
审查重点 3：工程实践是否可行？
  → 使用 GPT-4 或 DeepSeek（工程经验丰富）
  
审查重点 4：文档可读性如何？
  → 使用 GLM-5.3（中文理解好）
```

### GLM-5.3 审查的注意事项

#### 1. 上下文窗口限制

**问题**：GLM-5.3 的上下文窗口可能比 Claude 小

**解决方案**：
```yaml
策略 1：分段输入
  - 每次输入 1-2 个文档
  - 每个文档限制在 10,000 字以内
  - 让模型先消化，再给下一个

策略 2：摘要输入
  - 提供文档摘要而非全文
  - 重点部分给全文
  - 用 core/README.md 的推荐阅读顺序

策略 3：关键片段
  - 只输入需要审查的关键部分
  - 如：Contract 定义、Phase 0 计划、退出条件等
```

---

#### 2. 中文理解优势

**利用优势**：
- 让 GLM 审查文档的中文可读性
- 审查是否符合国内工程实践
- 审查术语翻译是否准确

**审查提示**：
```markdown
请从中文可读性角度审查这个方案：
1. 术语使用是否准确？（Skill、Harness、Contract、Protocol）
2. 表述是否符合中文习惯？
3. 是否有歧义或难以理解的地方？
4. 建议如何改进？
```

---

#### 3. 本土化审查

**审查重点**：
```yaml
国内场景适用性：
  - Phase 0 的 11 个任务追踪在国内是否可行？
  - 44 小时投入在国内团队是否现实？
  - Contract/Protocol 机制是否适合国内团队？
  - 文档复杂度是否适合国内工程师？

国内工程实践：
  - 是否符合敏捷开发习惯？
  - 是否符合国内代码审查流程？
  - 是否考虑国内团队规模（通常较小）？
```

## 📊 多模型审查结果对比

### 对比维度

```yaml
维度 1：发现的问题
  - Claude 发现：X 个
  - GPT-4 发现：Y 个
  - GLM-5.3 发现：Z 个
  - 重合：A 个（高优先级）
  - 独有：B 个（需要验证）

维度 2：评分对比
  - 方法论：Claude X/10, GPT-4 Y/10, GLM Z/10
  - 可行性：...
  - 收益：...
  - 总分：...

维度 3：关键建议
  - 三个模型都建议：优先采纳
  - 两个模型建议：考虑采纳
  - 单个模型建议：谨慎评估
```

---

### 分歧处理

**场景 1：评分分歧大**
```
Claude: 8.3/10
GPT-4: 7.5/10
GLM-5.3: 9.0/10

分析：
- 为什么 GLM 评分更高？→ 可能更认可中文文档质量
- 为什么 GPT-4 更低？→ 可能更关注工程实践细节
- 综合判断：取平均值或中位数
```

**场景 2：结论矛盾**
```
Claude: 建议启动
GPT-4: 建议先改进
GLM-5.3: 建议暂停

处理：
- 深入分析各自理由
- 识别分歧的根源（假设、视角、标准不同）
- 必要时增加第 4 个模型审查
```

## ✅ 推荐的多模型审查流程

### 流程 1：三模型交叉验证（最可靠）

```mermaid
Step 1: 准备工作（1h）
  - 整理审查材料
  - 设计审查提示词
  - 准备对比表格

↓

Step 2: 并行审查（各 2h，总 6h 工作量但可并行）
  - Claude 审查（方法论 + 批判性）
  - GPT-4 审查（可行性 + 工程实践）
  - GLM-5.3 审查（本土化 + 可读性）

↓

Step 3: 结果对比（1h）
  - 收集 3 份独立报告
  - 对比发现的问题
  - 对比评分和建议

↓

Step 4: 综合判断（1h）
  - 一致结论：高可信度
  - 分歧分析：深入思考
  - 最终决策：启动/改进/暂停

总时间：3h（串行）或 9h（如果不能并行）
```

---

### 流程 2：两阶段审查（效率优先）

```
阶段 1: GLM-5.3 快速筛查（30 分钟）
  - 判断是否值得深入
  - 识别明显问题
  
  决策：
    ✅ 值得 → 进入阶段 2
    ❌ 不值得 → 给出理由，暂停

---

阶段 2: GPT-4 深度审查（2 小时）
  - 全面评估
  - 批判性分析
  - 给出最终建议

总时间：2.5 小时
```
