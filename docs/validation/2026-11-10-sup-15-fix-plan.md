# SUP-15 修复计划：持久状态收敛判定

**日期：** 2026-11-10  
**问题：** 持久状态的 stop_reason 可直接冒充收敛判定  
**优先级：** P2  
**Phase：** 4

## 问题分析

### 当前实现问题

**位置：** `skills/autoresearch/scripts/orchestrate.sh:240-246`

```python
elif state.get("stop_reason"):
    verdict = state["stop_reason"]  # 直接使用 stop_reason，不验证
elif state.get("predicate_met") is True:
    # ... 正常收敛逻辑
```

**问题：**
- `validate-state` 不约束 `stop_reason` 字段的合法性
- `verdict` 命令在检查 `predicate_met` 之前直接返回 `stop_reason` 值
- 损坏或手工编辑的恢复状态能携带 `CONVERGED`，绕过"仅验证完成且 predicate met 才收敛"的约束

### 隔离复现

**输入状态：**
```json
{
  "goal": "test",
  "archetype": "test",
  "mode": "loop",
  "pipeline": ["verify"],
  "terminal_choice": "stop-at-verified",
  "hop_log": [],
  "cycle_count": 1,
  "predicate_met": false,
  "units_remaining": [2, 1],
  "stop_reason": "CONVERGED"
}
```

**当前行为：**
- `validate-state` → exit 0 / "valid"
- `next-hop` → exit 0 / "regression"
- `verdict` → exit 0 / "CONVERGED"

**矛盾：** predicate_met=false 但 verdict=CONVERGED

## 修复方案

### 1. 约束 stop_reason 合法值

在 `validate-state` 中添加 `stop_reason` 校验：

```python
VALID_STOP_REASONS = {"EXTERNAL-STOP", "USER-INTERRUPT", "ERROR"}

# 在 cmd_validate_state 中添加
if "stop_reason" in state:
    if not isinstance(state["stop_reason"], str):
        issues.append("stop_reason: must be a string when present")
    elif state["stop_reason"] not in VALID_STOP_REASONS:
        issues.append(f"stop_reason: must be one of {sorted(VALID_STOP_REASONS)}")
```

### 2. 修改 verdict 逻辑

确保成功状态必须由 predicate 与未解决信号共同导出：

```python
elif state.get("stop_reason"):
    # stop_reason 只能是中断原因，不能是成功收敛
    verdict = state["stop_reason"]
elif state.get("predicate_met") is True:
    # 只有 predicate_met=True 才能输出 CONVERGED 或 PENDING-SHIP-APPROVAL
    pipeline = state.get("pipeline") or []
    verdict = ("PENDING-SHIP-APPROVAL"
               if state.get("terminal_choice") == "proceed-to-ship" and "ship" in pipeline
               else "CONVERGED")
```

**关键约束：**
- `stop_reason` 只能包含非成功的停止原因（外部中断、用户取消、错误）
- `CONVERGED` 和 `PENDING-SHIP-APPROVAL` 只能通过 `predicate_met=True` 导出
- 不允许在状态中直接携带成功 verdict

### 3. 补充测试

新增回归测试覆盖：
- 合法 stop_reason（如 "EXTERNAL-STOP"）被接受
- 非法 stop_reason（如 "CONVERGED"）被 validate-state 拒绝
- predicate_met=false + stop_reason="CONVERGED" 组合被拒绝
- predicate_met=true 正常输出 CONVERGED（无 stop_reason 干扰）

## 风险评估

**低风险：**
- 只添加约束，不改变合法状态的处理
- 现有合法状态不会携带 "CONVERGED" 作为 stop_reason
- validate-state 拒绝会阻止错误状态进入 verdict

**注意事项：**
- 如果有历史状态文件包含非法 stop_reason，修复后会被明确拒绝
- 应确保 VALID_STOP_REASONS 覆盖所有合法的中断原因
