# spec-first 项目战略与全流程验证报告（2026-07-26）

## 0. TL;DR

**项目的瓶颈不在能力，而在兑现与采纳。** 确定性地板经本轮全流程实证验证是扎实的：typecheck 187 文件、skill 入口 lint 313 文件、单测 131 套件 1336 例、mcp-setup 30 套件 430 例全部通过；发布包 687 文件零禁入路径混入、零生产依赖；从真实 tarball 安装到 init/doctor 的端到端链路在全新仓库全部 PASS；35 个 skill 全部具备 SKILL.md 与治理注册，核心链路 Codebase→Spec→Plan→Tasks→Code→Review→Knowledge 七环节入口齐备。

但外部采纳接近零（周下载约 247、62 star、8 fork、1 open issue，2026-07-26 一手数据），且 v1.13.2 发布（2026-07-07）后已积压 **141 个未发版提交**。业界侧，流程编排层正被宿主与 spec-kit 快速商品化（Agent OS v3 主动砍掉自身 70% 是直接前车之鉴），而 spec-first 押注的证据链 / 可信收敛 / 知识沉淀层仍是全行业空白。**战略结论：立即从「继续加能力」切换到「清偿发布债 + 收缩维护面 + 让已有价值可被看见、可被独立试用」。**

## 4. 业界格局与定位（advisory，2026-07 网络调研）

**已商品化（不要再投入竞争）**：spec→plan→tasks→implement 的模板与多宿主命令生成（GitHub spec-kit，约 11 万 star、30+ agent 支持）；轻量 brownfield delta-spec 叙事（OpenSpec，约 5 万 star，Stores beta）；宿主原生 plan mode、subagent/Agent Teams、plugins/marketplace、checkpoint、worktree 并行（Claude Code 2026.6；Codex 0.145 补齐 subagent/memories）。**Agent OS v3（2026-01）主动砍掉自身 70% 框架、承认宿主 plan mode 吞掉其编排价值，是第三方 harness 被商品化侵蚀的最直接实证。**

**仍是空白（差异化窗口）**：跨宿主 evidence chain / verification gate（直接回应业界对 SDD「spec drift、假完成」的批评浪潮——Kent Beck/Fowler/ThoughtWorks 2026 上半年的 SDD 反弹期实际利好「证据优先」定位）；多 agent 并行后的**语义收敛与可信验证层**（业界共识「隔离是简单的一半，recombination 才是难点」，产品化方案为零）；verified 知识沉淀与复用（Tessl 方向摇摆）。

**定位结论（收紧既有定位，无需转向）**：

> spec-first 不是 another SDD 工具（该入口 spec-kit 已赢），而是 AI coding 的**证据与验证层**——spec-kit 们定义「做什么」，spec-first 证明「做没做对」。差异化能力应可被 spec-kit / OpenSpec 用户**不换工具**即可采用（互操作消费其产物做 review/verification/compound 闭环），而非全有或全无的整套安装。

## 5. 优化点清单（合并战略级与验证级）

**P0**
1. **发布债清偿**：141 个未发版提交、版本未 bump、工作分支未回 main——先发版再谈其他；这也是「价值可被试用」的前提（npm 上的 1.13.2 已落后本地 15 天）。
2. **战略与执行脱节**：STRATEGY.md 缺失、Milestone 表超期未复核、P-friction 审计搁置——机制都在，欠执行。
3. **采纳漏斗为零**：无 5 分钟可独立验证价值的路径（README 首屏被 preview 宿主 caveat 与 Graphify 细节占据）；无对外差异化叙事内容。

**P1**
4. 维护面超单人产能：35 skill × 5 宿主 × 契约测试的组合税吞掉全部演化产能；preview 宿主 ×3 应显式降级为维护冻结。
5. 差异化能力不可独立采用：evidence gate / honest-closeout 深埋全套 workflow，外部工具链用户无法单独消费。
6. 并行收敛需求（2026-06-30-003，已完成 brainstorm+doc-review）停滞在 plan 之前，而该层窗口正在收窄。
7. 本仓库 2 处 session-start hook drift（`spec-first init` 可修）+ 验证流程缺全局状态快照/恢复步骤。

**P2**
8. templates↔governance 17/16 对齐缺契约测试，plugin 交付面疑点待证实或证伪。
9. `spec-proof` 缺 `user-invocable: false` 标记；CHANGELOG 1 处时间倒挂；2 个 plan 缺 spec_id/origin；README 12 项覆盖缺口。

## 6. 指导方针与分阶段行动

**指导方针**：① 一个季度内新增能力默认冻结（Adopt/Thin/Retire 优先于 Build）；② 只在宿主不会免费提供的两层加注——跨宿主证据链/verification gate、并行 agent 可信收敛；③ 主动收缩维护面（聚焦 Claude+Codex，preview 宿主冻结）；④ 叙事互补而非对抗（做 spec-kit/OpenSpec 的下一层，借其流量入口）。**Non-goals**：GUI/看板编排、30+ 宿主覆盖、SaaS、prompt-collection 化、重建宿主 primitive。

**Phase 0（本周，低成本）**：发版清偿发布债（回 main → bump → 走完整 CI 门禁 → publish）；跑正式 `spec-strategy` 访谈固化 STRATEGY.md；复核 Milestone 表；顺手修 P2 小项（hook drift、spec-proof 标记、CHANGELOG 倒挂、templates 对齐契约测试）。

**Phase 1（约 1 个月，采纳最小闭环）**：执行 P-friction 摩擦审计（first-run 路径优先）；README/官网首屏重写为「证据与验证层」定位 + 5 分钟自验路径；发布一篇差异化叙事内容（SDD 批评者是对的——缺的不是更重的 spec，是证据闭环）；preview 宿主降级声明落到 README 与 doctor。

**Phase 2（本季度，差异化兑现）**：需求 003 进 `spec-plan` → 实施（并发检测 + 一键隔离 MVP）；设计 evidence gate 的可独立采用形态（只读消费 spec-kit/OpenSpec 产物起步）。

**Phase 3（数据驱动）**：依据摩擦审计与互操作试用信号，决定 sessions/knowledge 里程碑推进与 preview 宿主是否恢复投入。
