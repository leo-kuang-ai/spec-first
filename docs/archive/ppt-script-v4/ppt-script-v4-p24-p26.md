### 演讲提示

**时长控制**：4 分钟（±30 秒）
- 这是倒数第二页，可以稍详细

**语速建议**：
- 四个默认动作要清晰，每项停顿
- 四个验证信号要逐个说明，特别是"证明什么"
- 关键说明要慢

**互动设计**：
- "怎么知道新模式真的在运转"是个提问，停顿并观察

**备注栏内容**：
- 验证信号表是 v4.0 新增的，建立前后对应关系
- 第四个动作（沉淀）最容易被忽略，要特别强调
- 这一页是行动号召，很重要

**常见问题预案**：
- 如果有人问"两周够吗"，回答："两周是最小验证周期。关键不是完美，而是开始并观察这四个信号是否出现"

### Q&A 环节提示

**常见问题及回答要点**：

1. **"那我们团队现在就要全面切换到 AI First 吗？"**
   - 不是全面切换，是选可复用复杂任务试点
   - 从影响分析、测试补齐等边界清晰的场景开始
   - 观察四个验证信号是否出现

2. **"这套模式会不会增加前期设计成本？"**
   - 会，但成本在后续复用中摊销
   - P24.5 讲了适用边界，不是所有任务都要完整设计
   - 第一次可以轻量，第二次标准化，第三次验证

3. **"我的能力不够，是不是不适合用 AI？"**
   - 能力不够更需要用 AI，但要带着四个前提：保留独立判断、用外部证据校准、能解释为什么正确、沉淀经验
   - P20 给了每层能力的培养方法
   - 关键是在执行机会中建立能力，不是等能力具备了再开始

4. **"四个对象（Goal/Workflow/Gate/Authority）具体怎么写？"**
   - P12 给了问题模板
   - 建议先用文档工具写（Notion/飞书文档/Markdown），让团队可见
   - 后续可以考虑工具化，但先不要被工具限制

5. **"如果团队其他人不理解这套模式怎么办？"**
   - 不要一开始就推全员
   - 先自己在一个任务中试点，产生可观测结果
   - 用四个验证信号的出现说服其他人
   - 成功案例是最好的说服

6. **"这套模式适用于前端/后端/测试/运维吗？"**
   - 适用于所有需要"定义-执行-验证"闭环的研发工作
   - 具体的 Workflow 和 Gate 会不同，但四个对象的结构是通用的
   - 前端可能 Gate 侧重视觉还原和交互，后端侧重性能和数据正确性

7. **"多久能看到效果？"**
   - 单个任务：两周内能看到四个验证信号的初步迹象
   - 能力建设：3-6 个月能感受到明显变化
   - 团队习惯：6-12 个月形成新的协作模式
   - 关键是持续迭代，不是一次到位

8. **"如果 AI 出错了怎么办？"**
   - Gate 就是为这个设计的
   - AI 出错会在 Check 环节被发现，触发 Diagnose → Correct → Re-verify
   - 如果超出 Authority 或重试上限，会 Blocked 给人
   - 人的责任是定义 Gate 和 Authority，不是防止所有错误
