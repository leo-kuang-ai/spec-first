第一，权限规则。[停顿 1s] 哪些用户可以导出？[停顿] "沿用现有权限"是指什么？[停顿] 权限表在哪里？[停顿 1s] 没说。

[指向"敏感字段"]

第二，敏感字段。[停顿 1s] 哪些字段不能导出？[停顿] 脱敏规则是什么？[停顿 1s] 没说。

[指向"数据量处理"]

第三，数据量处理。[停顿 1s] 最大导出多少条？[停顿] 超过上限怎么办？[停顿 1s] 没说。

[指向"完成标准"]

第五，完成标准。[停顿 1s] 生成代码算完成？[停顿] 还是测试通过才算？[停顿 1s] 也没说。

好，第二类。

[翻页]

### 演讲提示

**时长控制**：2.5 分钟（±20 秒）

**语速建议**：
- 读原始需求时要慢，让观众记住
- 五类猜测项用相同节奏（类型 → 问题 → 没说）
- "执行越快，猜测被固化得越快"这句要重

**互动设计**：
- "很常见，对吧"是个轻互动，观察观众表情
- 如果有人点头或露出"确实如此"的表情，说明案例击中了

**备注栏内容**：
- 这个案例会贯穿到 P23，是全场唯一的具体案例
- 五类猜测项每项都要逐个指出，不要一次性读完
- 底部收束句是本页的核心 takeaway

**常见问题预案**：
- 如果有人问"那是不是每个需求都要写这么详细"，回答："不是每个细节都要写，但不可猜测的边界必须定义清楚"

### 演讲提示

**时长控制**：2 分钟（±15 秒）

**语速建议**：
- 描述等人循环时语速可以略快（营造"反复"的感觉）
- 三个缺失项每项后面都停顿并说"没有"
- 关键句要慢，这是核心 takeaway

**互动设计**：
- 这一页节奏较快，不适合中途互动
- 观察观众是否有"确实如此"的表情

**备注栏内容**：
- "等人"节点是视觉锚点，一定要指出来
- 这一页是在说"没有 Workflow"，完整的 Workflow（含自检纠偏）留到 P13
- 关键句区分了"自动化脚本"和"AI First 工作流"，这个概念后面会反复用到

**常见问题预案**：
- 如果有人问"那要定义到什么程度才算完整"，回答："至少要定义检查点、失败诊断和恢复路径，P12 会给出最小模板"

### 演讲提示

**时长控制**：2.5 分钟（±20 秒）

**语速建议**：
- 前两个勾的节奏要轻快（营造"看起来很顺"的假象）
- "可以上线吗"这个问题要慢，并停顿足够长
- 三个缺口的解释要清晰，每个例子都要说完整

**互动设计**：
- "这个问号，就是问题所在"是个强调点，观察观众反应
- 如果有人点头，说明他们也遇到过这个困境

**备注栏内容**：
- 三个勾到问号的转折是本页的关键张力
- Authority 的例子（权限判断）要说清楚，这是很多人容易混淆的地方
- 关键句是本页的核心 takeaway，也是后面 P14 Gate 设计的铺垫

**常见问题预案**：
- 如果有人问"那是不是要定义非常多的 Gate"，回答："不是数量多，是关键边界必须有证据。P14 会给出具体的 Gate 设计方法"
