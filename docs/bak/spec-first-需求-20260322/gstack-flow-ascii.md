## 4. 门禁视角图

这张图不是按业务流程画，而是按“哪里在兜底质量”画。

```text
新项目:
office-hours
   -> ceo-review
      -> eng-review [关键门禁]
         -> design-review(plan) [UI 项目强建议]
            -> 实现
               -> review
               -> qa [行为门禁]
                  -> ship [最终发布门禁]

存量项目:
明确需求
   -> eng-review [关键门禁]
      -> 实现
         -> review
         -> qa
            -> ship

bugfix:
investigate
   -> 修复
      -> review
         -> qa
            -> ship
```

## 5. 怎么读这几张图

### 新项目

重点是：

- 先把问题定义对
- 再把架构和设计锁住
- 然后再进入实现和验证

### 存量项目需求迭代

重点是：

- 如果需求已清晰，可以从 `/plan-eng-review` 起步
- 如果需求本身还不清晰，就先回到 `/office-hours` 和 `/plan-ceo-review`

### Bugfix / 排障

重点是：

- 不要跳过 `/investigate`
- 先查 root cause，再修，再验证，再发布

## 6. 一句话总结

```text
新项目 = 先想清楚再实现
存量迭代 = 先锁方案再改现有系统
bugfix = 先查根因再修复
```
