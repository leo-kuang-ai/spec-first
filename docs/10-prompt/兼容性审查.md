当前已有用户反馈：`spec-first` 在 Windows 下存在兼容性问题，尤其是在 **Windows PowerShell** 环境中运行时可能出现异常。因此需要对整个仓库进行全面审查，识别所有跨平台风险。

审查范围不仅包括代码本身，也包括：

* README / 文档中的命令示例
* scripts 脚本
* skills / agents 中的命令调用
* MCP / helper / provider 配置与初始化
* 路径拼接
* 文件读写
* shell 命令
* 环境变量
* 临时目录
* 编码与换行
* npm / node / python / bash / git 调用
* CI / 本地验证命令
* 用户安装、初始化、运行、验证全链路

## 二、审查目标

请完成一次系统性审查，判断当前仓库是否可以在以下环境中稳定运行：

1. Windows 11 + PowerShell 5.1
2. Windows 11 + PowerShell 7+
3. Windows Terminal + PowerShell
4. Git Bash on Windows
5. WSL 环境
6. macOS / Linux 原有环境是否会因修复 Windows 兼容性而回归

重点不是只找显性 bug，而是识别所有 **Windows 下高概率失败点**，并输出可执行的修复建议。

## 三、必须重点审查的问题类型

### 1. 路径兼容性

重点检查是否存在：

* 硬编码 `/` 路径分隔符
* 依赖 Unix 风格绝对路径，例如 `/tmp`、`/usr/bin/env`、`/bin/bash`
* 使用字符串拼接路径而非跨平台 path API
* 未处理 Windows 盘符路径，例如 `C:\Users\xxx`
* 未处理路径中包含空格，例如 `C:\Users\Charles Green\project`
* 未对路径加引号
* glob 匹配在 Windows 下行为不同
* 相对路径基于错误 cwd
* 使用 shell 命令解析路径导致反斜杠转义失败

请重点搜索：

* `/tmp`
* `/bin/bash`
* `#!/bin/bash`
* `#!/usr/bin/env bash`
* `path.join` / `path.resolve` 使用是否正确
* 字符串形式的 `./xxx/yyy`
* `cwd`
* `process.cwd`
* `__dirname`
* `os.tmpdir`
* `HOME`
* `USERPROFILE`
* `APPDATA`

### 2. Shell / PowerShell 命令兼容性

重点检查是否存在只能在 bash/zsh 下运行的命令：

* `cp`
* `mv`
* `rm -rf`
* `mkdir -p`
* `touch`
* `cat`
* `grep`
* `sed`
* `awk`
* `find`
* `xargs`
* `chmod`
* `export VAR=xxx`
* `VAR=value command`
* `source`
* `which`
* `curl | bash`
* here-doc：`cat <<EOF`
* 管道和重定向语法差异
* 单引号、双引号、反引号在 PowerShell 下语义差异
* `&&`、`||` 在 PowerShell 5.1 下兼容性
* npm scripts 中调用 Unix 命令

请判断每一处命令是否可以在 PowerShell 5.1 / PowerShell 7 / Git Bash / WSL 下运行。

### 3. npm / pnpm / node 脚本兼容性

如果仓库中存在 Node.js 相关脚本，请重点检查：

* package.json scripts 是否包含 Unix-only 命令
* 是否依赖 `cross-env`
* 是否使用 `NODE_ENV=production` 这类 PowerShell 不兼容写法
* 是否使用 `rm -rf dist`
* 是否使用 `cp -r`
* 是否使用 `mkdir -p`
* 是否有路径未加引号
* 是否调用 bash 脚本
* 是否需要提供 `.cmd` / `.ps1` 替代入口
* 是否需要统一封装为 Node 脚本以替代 shell 脚本

### 4. Python 脚本兼容性

如果仓库中存在 Python 脚本，请重点检查：

* 是否使用硬编码 Unix 路径
* 是否使用 `subprocess(..., shell=True)` 调用 Unix 命令
* 是否使用 `/tmp`
* 是否使用 `open(..., encoding=...)` 不明确导致中文乱码
* 是否存在 Windows 下换行差异导致解析失败
* 是否假设可执行文件有 chmod 权限
* 是否使用 pathlib 替代字符串路径
* 是否正确处理 PowerShell 传参和引号

### 5. 文件编码与换行

重点检查：

* 是否有文件默认编码依赖系统 locale
* 是否统一使用 UTF-8
* 是否在 Windows 下读取中文文档、markdown、json、yaml 出现乱码
* 是否处理 CRLF / LF 差异
* 是否脚本在 CRLF 下执行失败
* 是否需要 `.gitattributes`
* 是否需要指定文本文件换行策略
* 是否需要规范 shell 脚本保持 LF
* 是否需要规范 PowerShell 脚本使用 UTF-8

### 6. 可执行权限与脚本入口

Windows 不依赖 Unix chmod，因此请重点检查：

* 是否假设脚本已有 executable bit
* 是否文档要求 `chmod +x`
* 是否 CLI 入口依赖 shebang
* 是否在 Windows 下需要通过 `node xxx.js` / `python xxx.py` / `pwsh xxx.ps1` 调用
* 是否 npm bin 配置能在 Windows 下生成 `.cmd`
* 是否存在 shell 脚本无法直接运行的问题

### 7. 环境变量兼容性

重点检查：

* Unix 写法：`export KEY=value`
* Windows PowerShell 写法：`$env:KEY="value"`
* CMD 写法：`set KEY=value`
* npm scripts 中环境变量设置是否跨平台
* 是否区分 `HOME`、`USERPROFILE`、`APPDATA`
* 是否正确读取用户目录、缓存目录、配置目录
* 是否文档同时提供 Windows / macOS / Linux 示例

### 8. Git / MCP / helper / provider 配置兼容性

重点检查 spec-first 的核心流程是否存在 Windows 风险：

* MCP 配置文件路径是否跨平台
* helper-tools.json / mcp-tools.json / provider 配置是否使用 Unix 路径
* readiness facts / runtime capabilities 输出路径是否跨平台
* scenario fingerprint 是否受路径分隔符影响
* workspace 初始化是否可在 Windows 下执行
* Git 命令是否依赖 bash
* Git hook 是否在 Windows 下可用
* 是否存在符号链接 symlink 兼容性问题
* 是否存在文件名大小写敏感差异

### 9. 文档与用户命令示例兼容性

请全面审查 README、docs、skills 文档中的命令示例，判断：

* 是否只给了 macOS / Linux 命令
* 是否缺少 Windows PowerShell 版本
* 是否存在复制到 PowerShell 直接失败的命令
* 是否需要增加 Windows 专区
* 是否需要明确推荐 PowerShell 7、Git Bash 或 WSL
* 是否需要区分普通用户安装和开发者调试
* 是否需要增加“Windows 常见问题排查”

### 10. 测试与验证

请检查仓库是否具备 Windows 验证能力：

* 是否有 GitHub Actions Windows matrix
* 是否覆盖 `windows-latest`
* 是否验证 PowerShell 下的安装、初始化、运行、核心 workflow
* 是否有最小 smoke test
* 是否有路径中带空格的测试
* 是否有中文路径测试
* 是否有 CRLF / LF 测试
* 是否有文档命令可执行性测试
* 是否需要新增 `scripts/verify-windows.ps1`

包括：

* 文档补充 PowerShell 命令
* 替换明显 Unix-only 命令
* 增加 Windows smoke test
* 增加路径加引号
* 明确推荐 PowerShell 7 或 Git Bash / WSL

#### 第二阶段：跨平台抽象

目标：消除 shell 依赖。

包括：

* 将复杂 shell 脚本迁移为 Node/Python 跨平台脚本
* 统一 path API
* 统一环境变量处理
* 统一临时目录、配置目录
* 增加 `.gitattributes`
* 增加 Windows CI matrix

#### 第三阶段：长期治理

目标：建立 spec-first 跨平台兼容性基线。

包括：

* 新增跨平台编码规范
* 新增文档命令验证
