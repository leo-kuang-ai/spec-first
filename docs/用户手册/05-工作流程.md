# 工作流程

本指南介绍使用 Spec-First 的推荐工作流程,帮助你最大化效率。

## 🎯 核心理念

### Spec-First 方法论

**先规划,后编码** - 通过结构化的规划流程,确保代码实现符合产品目标。

```
产品想法 → 深度规划 → 工程设计 → 实现 → 测试 → 发布
```

### 黄金法则

1. **没有规划不编码** - 先运行 `/brainstorm` 或 `/plan-eng-review`
2. **没有审查不发布** - 运行 `/review` 和 `/qa`
3. **没有验证不部署** - 运行 `/canary` 监控

## 🚀 标准工作流程

### 场景 1: 新功能开发

完整的从想法到部署流程:

```
┌─────────────────────────────────────────────────────────────┐
│ 第 1 阶段: 产品规划 (1-2 小时)                                │
├─────────────────────────────────────────────────────────────┤
│ 1. /brainstorm          → 生成设计文档                     │
│ 2. /plan-ceo-review       → CEO 视角审查                     │
│ 3. /plan-eng-review       → 工程实现规划                     │
│ 4. /plan-design-review    → UX/设计审查 (可选)               │
└─────────────────────────────────────────────────────────────┘
          ↓
┌─────────────────────────────────────────────────────────────┐
│ 第 2 阶段: 实现 (数小时到数天)                                │
├─────────────────────────────────────────────────────────────┤
│ 1. Claude 根据设计文档自动实现                               │
│ 2. 分步实现,每个功能点单独测试                               │
│ 3. 遇到问题时运行 /investigate                              │
└─────────────────────────────────────────────────────────────┘
          ↓
┌─────────────────────────────────────────────────────────────┐
│ 第 3 阶段: 质量保证 (30-60 分钟)                              │
├─────────────────────────────────────────────────────────────┤
│ 1. /review                → 代码审查                         │
│ 2. /qa                    → 完整 QA 测试                     │
│ 3. 修复发现的问题                                         │
│ 4. 重新运行 /review 和 /qa                                │
└─────────────────────────────────────────────────────────────┘
          ↓
┌─────────────────────────────────────────────────────────────┐
│ 第 4 阶段: 发布 (15-30 分钟)                                  │
├─────────────────────────────────────────────────────────────┤
│ 1. /ship                  → 创建 PR                          │
│ 2. 等待团队审查                                           │
│ 3. /land-and-deploy       → 合并和部署                       │
│ 4. /canary                → 生产监控 (30 分钟)               │
└─────────────────────────────────────────────────────────────┘
```

**总时间**: 2-8 小时 (取决于功能复杂度)

### 场景 2: Bug 修复

系统化的调试和修复流程:

```
┌─────────────────────────────────────────────────────────────┐
│ 第 1 阶段: 问题诊断 (15-30 分钟)                              │
├─────────────────────────────────────────────────────────────┤
│ 1. /freeze                → 锁定编辑范围                     │
│ 2. /investigate           → 根因分析                         │
│ 3. 确认假设                                              │
└─────────────────────────────────────────────────────────────┘
          ↓
┌─────────────────────────────────────────────────────────────┐
│ 第 2 阶段: 修复实现 (15-60 分钟)                              │
├─────────────────────────────────────────────────────────────┤
│ 1. 实现最小修复                                           │
│ 2. 编写回归测试                                           │
│ 3. 运行测试套件                                           │
└─────────────────────────────────────────────────────────────┘
          ↓
┌─────────────────────────────────────────────────────────────┐
│ 第 3 阶段: 验证 (15-30 分钟)                                  │
├─────────────────────────────────────────────────────────────┤
│ 1. /review                → 代码审查                         │
│ 2. /qa                    → QA 验证                         │
│ 3. 确认问题已解决                                         │
└─────────────────────────────────────────────────────────────┘
          ↓
┌─────────────────────────────────────────────────────────────┐
│ 第 4 阶段: 发布 (15 分钟)                                     │
├─────────────────────────────────────────────────────────────┤
│ 1. /ship                  → 创建热修复 PR                    │
│ 2. /land-and-deploy       → 快速合并部署                     │
│ 3. /canary --quick        → 快速验证                         │
└─────────────────────────────────────────────────────────────┘
```

**总时间**: 1-2.5 小时

性能优化的系统化流程:

```
┌─────────────────────────────────────────────────────────────┐
│ 第 1 阶段: 基线建立 (30 分钟)                                  │
├─────────────────────────────────────────────────────────────┤

├─────────────────────────────────────────────────────────────┤
│ 1. /benchmark             → 性能对比                         │
│ 2. 验证改进效果                                           │
│ 3. /qa                    → 确保功能正常                     │
└─────────────────────────────────────────────────────────────┘
          ↓
┌─────────────────────────────────────────────────────────────┐
│ 第 4 阶段: 发布 (30 分钟)                                      │
├─────────────────────────────────────────────────────────────┤
│ 1. /ship                  → 创建性能优化 PR                  │
│ 2. /land-and-deploy       → 部署                             │
│ 3. /canary                → 生产环境性能监控                 │
```

## 🔄 日常工作流程

### 每日例行

```bash
# 早上: 开始工作
/retro                    # 查看昨日统计

# 开始新任务
/brainstorm             # 规划今天的工作

# 工作中
/freeze src/auth         # 限制修改范围 (可选)

# 完成任务
/review                   # 代码审查
/qa                       # QA 测试

# 下班前
/ship                     # 提交 PR
```

### 每周例行

```bash
# 周五: 周报
/retro                    # 本周统计和回顾

# 代码清理
/review                   # 全面的代码审查
/document-release         # 更新文档

# 性能检查
/benchmark --trend        # 查看性能趋势
```

### 发布日例行

```bash
# 发布前
/review                   # 最终审查
/qa --exhaustive          # 完整测试

# 发布
/ship                     # 创建发布 PR
/land-and-deploy          # 合并和部署

# 发布后
/canary --duration 1h     # 1 小时监控
/benchmark                # 性能验证
```

## 🎓 进阶技巧

### 1. 并行运行技能

某些技能可以并行运行以节省时间:

```bash
# 并行运行审查
/review &
/codex review &
wait

# 并行运行测试
/qa --quick &
/benchmark &
wait
```

### 2. 自动化工作流

创建自定义脚本:

```bash
# 保存为 ~/bin/full-release.sh
#!/bin/bash
/review && /qa && /ship && /land-and-deploy && /canary
```

### 3. 条件化流程

根据结果决定下一步:

```bash
# 如果 QA 失败,不继续发布
/qa && /ship || echo "Fix issues first"
```
