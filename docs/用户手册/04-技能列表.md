# 技能列表

Spec-First 包含 **25+ 个专业技能**,覆盖从产品规划到部署监控的完整开发流程。

## 📋 技能分类

### 🎯 产品规划类

#### `/brainstorm` - 头脑风暴

**用途**: 产品规划和问题诊断

**使用场景**:
- 有一个产品想法,需要深入分析
- 想挑战产品前提和范围
- 需要生成设计文档

**输出**: 设计文档 (`~/.spec-first/projects/`)

**示例**:
```
/brainstorm
我想构建一个每日简报应用,帮助管理多个日历...
```

---

#### `/plan-ceo-review` - CEO 模式审查

**用途**: 从 CEO 视角审查计划,思考更大

**使用场景**:
- 产品计划需要扩展视野
- 想找到 10x 产品机会
- 需要挑战产品范围

**4 种模式**:
- **SCOPE EXPANSION** - 扩大范围
- **SELECTIVE EXPANSION** - 选择性扩展
- **HOLD SCOPE** - 保持范围
- **SCOPE REDUCTION** - 精简范围

**前置**: 通常在 `/brainstorm` 后运行

---

#### `/plan-eng-review` - 工程经理模式审查

**用途**: 锁定工程计划

**使用场景**:
- 需要审查架构设计
- 检查边缘情况和测试覆盖
- 评估性能和安全性

**输出**:
- 架构审查报告
- 测试计划
- 性能评估

**前置**: 通常在 `/plan-ceo-review` 后运行

---

#### `/plan-design-review` - 设计师模式审查

**用途**: 设计和 UX 审查

**使用场景**:
- UI/UX 设计需要审查
- 视觉一致性检查
- 交互流程优化

**输出**: 设计评分和改进建议

---

### 💻 开发类

#### `/review` - 代码审查

**用途**: 自动化代码审查

**使用场景**:
- 提交 PR 前的代码审查
- 检查安全问题和最佳实践
- 发现潜在 bug

**检查项**:
- SQL 安全
- LLM 输出信任边界
- 条件副作用
- 结构问题

**输出**: 审查报告 + 自动修复

---

#### `/investigate` - 系统化调试

**用途**: 根因分析和 bug 修复

**使用场景**:
- 调试复杂问题
- 需要找到根本原因
- 系统性排查 bug

**铁律**: **没有找到根因就不修复**

**输出**: DEBUG REPORT

---

#### `/codex` - Codex CLI 集成

**用途**: OpenAI Codex 独立审查

**使用场景**:
- 需要第二意见
- 独立代码审查
- 挑战代码逻辑

**3 种模式**:
- **review** - 代码审查
- **challenge** - 对抗模式
- **consult** - 咨询模式

---

### 🧪 测试类

#### `/qa` - QA 测试和修复

**用途**: 完整的 QA 测试循环

**使用场景**:
- 功能完成后需要测试
- 自动发现和修复 bug
- 生成测试报告

**3 个层级**:
- **Quick** - 仅关键和高优先级
- **Standard** - 包含中优先级
- **Exhaustive** - 包含低优先级

**输出**:
- 健康评分
- Bug 报告
- 修复提交

---

#### `/qa-only` - 仅 QA 报告

**用途**: 仅测试,不修复

**使用场景**:
- 只想了解问题
- 不想自动修复
- 报告模式

**输出**: 详细测试报告

---

#### `/canary` - 部署后监控

**用途**: 生产环境监控

**使用场景**:
- 刚部署到生产
- 需要监控稳定性
- 检测性能回归

**监控项**:
- 控制台错误
- 页面加载时间
- 视觉变化

**输出**: 监控报告 + 告警

---

#### `/benchmark` - 性能回归检测

**用途**: 性能基线和对比

**使用场景**:
- 性能优化前后对比
- 建立性能基线
- 检测性能退化

**指标**:
- 页面加载时间
- Core Web Vitals
- 资源大小

**输出**: 性能报告 + 趋势图

---

### 🚀 部署类

#### `/ship` - 自动发布流程

**用途**: 一键发布 PR

**使用场景**:
- 代码完成,准备发布
- 需要自动化的发布流程
- 生成 CHANGELOG

**流程**:
1. 合并基础分支
2. 运行测试
3. 代码审查
4. 版本升级
5. 更新 CHANGELOG
6. 创建 PR

**输出**: PR URL

---

#### `/land-and-deploy` - 合并和部署

**用途**: 合并 PR 并部署

**使用场景**:
- PR 审查通过
- 准备部署到生产
- 需要验证部署

**流程**:
1. 检查 CI 状态
2. 等待审查通过
3. 合并 PR
4. 等待部署
5. 生产验证

**输出**: 部署报告

---

#### `/setup-deploy` - 配置部署

**用途**: 配置部署设置

**使用场景**:
- 第一次部署
- 需要配置部署平台
- 更新部署配置

**支持平台**:
- Fly.io
- Render
- Vercel
- Netlify
- Heroku
- GitHub Actions
- 自定义

**输出**: CLAUDE.md 配置

---

**使用场景**:

#### `/design-review` - 设计审查

**用途**: 视觉审查和修复

**使用场景**:
- UI 实现后需要审查
- 视觉不一致
- AI 生成的 UI 检查

**检查项**:

- 间距问题

**输出**: 设计问题 + 自动修复

---

### 🔒 安全类

#### `/careful` - 危险命令警告

**用途**: 破坏性命令保护

**使用场景**:
- 需要执行危险操作
- 防止意外删除
- 生产环境保护

**保护命令**:
- `rm -rf`
- `DROP TABLE`
- `git push --force`
- `git reset --hard`
- `kubectl delete`

**输出**: 警告 + 确认

---

#### `/freeze` - 限制编辑范围

**用途**: 目录级别的编辑限制

**使用场景**:
- 调试时防止误改
- 限制修改范围
- 保护关键代码

**输出**: 编辑边界锁定

---

#### `/guard` - 完整安全模式

**用途**: 组合安全保护

**使用场景**:
- 需要最大安全性
- 生产环境操作
- 关键系统修改

**组合**: `/careful` + `/freeze`

---

## 🎯 推荐技能组合

### 新项目启动

```
1. /brainstorm          # 产品规划
2. /plan-ceo-review       # CEO 审查
3. /plan-eng-review       # 工程审查
4. /design-consultation   # 设计系统
```

### 功能开发

```
1. /brainstorm          # 功能设计
2. /plan-eng-review       # 工程规划
3. (实现代码)
4. /review                # 代码审查
5. /qa                    # QA 测试
```

### 发布流程

```
1. /review                # 最终审查
2. /qa                    # 完整测试
3. /ship                  # 创建 PR
4. /land-and-deploy       # 合并部署
5. /canary                # 生产监控
```

### 调试流程

```
1. /freeze                # 限制范围
2. /investigate           # 根因分析
3. (修复代码)
4. /review                # 代码审查
5. /qa                    # 测试验证
```
