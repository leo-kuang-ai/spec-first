# 贡献指南

感谢你对 Spec-First 的兴趣!我们欢迎所有形式的贡献。

## 🤝 贡献方式

### 1. 报告 Bug

发现 Bug?请提交 Issue!

**提交前检查**:
- [ ] 搜索现有 Issues,避免重复
- [ ] 使用最新版本测试
- [ ] 准备好复现步骤

**Issue 模板**:

```markdown
## Bug 描述
简要描述问题

## 复现步骤
1. 运行 '...'
2. 点击 '...'
3. 看到错误

## 期望行为
应该发生什么

## 实际行为
实际发生了什么

## 环境
- Spec-First 版本: [e.g. v1.0.0]
- 操作系统: [e.g. macOS 14.0]
- Bun 版本: [e.g. 1.0.0]

## 附加信息
- 截图
- 日志
- 配置文件
```

### 2. 建议新功能

有好的想法?我们想听听!

**功能请求模板**:

```markdown
## 功能描述
清晰描述你想要的功能

## 使用场景
为什么需要这个功能?如何使用?

## 可能的实现
如果有想法,简要描述实现方式

## 替代方案
考虑过哪些其他方案?
```

### 3. 改进文档

文档永远可以更好!

**可以改进的地方**:
- 修复拼写错误
- 改进说明
- 添加示例
- 翻译文档

### 4. 贡献代码

想写代码?太棒了!

## 🛠️ 开发设置

### 1. Fork 和 Clone

```bash
# Fork 仓库到你的账号
# 然后:
git clone https://github.com/YOUR_USERNAME/spec-first.git
cd spec-first

# 添加上游仓库
git remote add upstream https://github.com/original/spec-first.git
```

### 2. 安装依赖

```bash
bun install
```

### 3. 运行测试

```bash
# 运行所有测试
bun test

# 运行特定测试
bun test skill-validation
```

### 4. 构建项目

```bash
# 构建所有
bun run build

# 仅生成文档
bun run gen:skill-docs

# 仅构建 browse
bun run build:browse
```

## 📝 代码规范

### Bash 脚本

```bash
# ✅ 好的做法
#!/bin/bash
set -euo pipefail

# 描述性变量
STATE_DIR="${CLAUDE_PLUGIN_DATA:-$HOME/.spec-first}"
PROJECT_NAME=$(basename "$(pwd)")

# 错误处理
if [ ! -f "required-file" ]; then
  echo "Error: required-file not found" >&2
  exit 1
fi

# 清晰的输出
echo "Processing $PROJECT_NAME..."
```

### TypeScript

```typescript
// ✅ 好的做法
interface SkillConfig {
  name: string;
  version: string;
  allowedTools: string[];
}

function parseSkillConfig(content: string): SkillConfig {
  // 清晰的错误消息
  if (!content) {
    throw new Error('Skill config content is empty');
  }

  // 类型安全
  const config = parseYaml(content) as SkillConfig;

  // 验证
  validateConfig(config);

  return config;
}
```

### Markdown

```markdown
<!-- ✅ 好的做法 -->

## 标题使用 ATX 风格

段落简洁明了。

**强调**使用粗体,`代码`使用反引号。

```bash
# 代码块指定语言
echo "Hello"
```

- 列表项简洁
- 一个想法一项

---

<!-- ❌ 避免 -->

##不要跳级

段落冗长啰嗦,没有重点,读者很难理解你的意思,容易迷失在文字中。

代码块不指定语言:
```
echo "这很难读"
```
```

### 提交信息

```bash
# ✅ 好的提交信息
feat: add /qa --regression mode for baseline comparison
fix: correct browse binary path in setup script
docs: update installation guide for Windows
refactor: simplify skill template parser
test: add integration tests for /ship workflow

# ❌ 避免
fix bug
update
WIP
asdfasdf
```

**格式**: `<type>(<scope>): <subject>`

**类型**:
- `feat`: 新功能
- `fix`: Bug 修复
- `docs`: 文档
- `refactor`: 重构
- `test`: 测试
- `chore`: 杂项

## 🧪 测试

### 运行测试

```bash
# 所有测试
bun test

# 快速测试 (免费)
bun test --free

# E2E 测试 (付费)
bun run test:e2e

# 特定测试
bun test skill-validation.test.ts
```

### 编写测试

```typescript
// test/my-feature.test.ts
import { describe, it, expect } from 'bun:test';

describe('My Feature', () => {
  it('should do something', () => {
    const result = myFunction('input');
    expect(result).toBe('expected output');
  });

  it('should handle errors', () => {
    expect(() => myFunction('invalid')).toThrow();
  });
});
```

## 📦 Pull Request 流程

### 1. 创建分支

```bash
# 从 main 创建功能分支
git checkout main
git pull upstream main
git checkout -b feature/my-feature

# 或修复分支
git checkout -b fix/issue-123
```

### 2. 进行更改

```bash
# 进行更改
vim skill/SKILL.md.tmpl

# 运行测试
bun test

# 生成文档
bun run gen:skill-docs

# 提交
git add -A
git commit -m "feat: add my feature"
```

### 3. 推送和创建 PR

```bash
# 推送到你的 fork
git push origin feature/my-feature

# 在 GitHub 上创建 Pull Request
```

### 4. PR 检查清单

```markdown
## 描述
简要描述你的更改

## 类型
- [ ] Bug 修复
- [ ] 新功能
- [ ] 文档更新
- [ ] 重构
- [ ] 测试

## 测试
- [ ] 添加了测试
- [ ] 所有测试通过
- [ ] 手动测试完成

## 文档
- [ ] 更新了相关文档
- [ ] 添加了示例
- [ ] 更新了 CHANGELOG

## Breaking Changes
- [ ] 无 Breaking Changes
- [ ] 有 Breaking Changes (已说明)

## 相关 Issues
Fixes #123
Related #456
```

### 5. Code Review

**响应反馈**:
- 保持开放心态
- 讨论技术问题
- 及时响应

**修改代码**:
```bash
# 根据反馈修改
vim skill/SKILL.md.tmpl

# 提交修改
git add -A
git commit -m "refactor: address review feedback"

# 推送
git push origin feature/my-feature
```

## 🎨 贡献技能

### 提交新技能

1. **检查是否已存在**
   - 搜索现有技能
   - 检查 Issues 和 PRs

2. **先提 Issue 讨论**
   - 描述技能用途
   - 说明使用场景
   - 讨论实现方案

3. **实现技能**
   - 遵循技能模板
   - 添加测试
   - 编写文档

4. **提交 PR**
   - 包含技能文件
   - 包含测试
   - 包含文档

### 技能质量标准

- [ ] 清晰的描述和使用场景
- [ ] 结构化的指令
- [ ] 错误处理
- [ ] 测试覆盖
- [ ] 文档完整
- [ ] 遵循命名规范

## 📋 行为准则

### 我们的承诺

为了营造开放和友好的环境,我们承诺:

- 使用包容性语言
- 尊重不同观点
- 优雅地接受建设性批评
- 关注对社区最有利的事情
- 对其他社区成员表示同理心

### 不可接受的行为

- 使用性化的语言或图像
- 捣乱、侮辱/贬损评论、人身攻击
- 公开或私下骚扰
- 未经许可发布他人私人信息
- 其他在专业环境中不适当的行为

### 执行

不可接受的行为可能导致永久封禁。
