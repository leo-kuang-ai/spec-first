## 🔧 安装问题

### Q1: 安装失败,提示 "bun: command not found"

**原因**: Bun 未安装或不在 PATH 中。

**解决方案**:
```bash
# macOS/Linux
curl -fsSL https://bun.sh/install | bash

# 重启终端
source ~/.bashrc  # 或 ~/.zshrc

# 验证
bun --version
```

---

### Q2: Windows 上安装失败

**原因**: Windows 需要 Node.js 来运行 Playwright。

**解决方案**:
```powershell
# 1. 安装 Node.js
# 下载: https://nodejs.org/

# 2. 验证
node --version

# 3. 安装 Spec-First
git clone https://github.com/sunrain520/spec-first.git $env:USERPROFILE\.claude\skills\spec-first
cd $env:USERPROFILE\.claude\skills\spec-first
.\setup
```

---

### Q3: Playwright 安装失败

**错误**: `Playwright browser installation failed`

**解决方案**:
```bash
cd ~/.claude/skills/spec-first

# 手动安装 Chromium
bunx playwright install chromium

# 如果还是失败,尝试
npx playwright install chromium
```

---

### Q4: 权限错误 "Permission denied"

**解决方案**:
```bash
# 给脚本执行权限
chmod +x ~/.claude/skills/spec-first/setup
chmod +x ~/.claude/skills/spec-first/bin/*

# 如果还是不行,检查目录权限
ls -la ~/.claude/skills/
```

## 🎯 使用问题

### Q5: 技能无法运行,提示 "skill not found"

**原因**: Claude Code 未找到技能文件。

**解决方案**:
```bash
# 1. 检查安装
ls ~/.claude/skills/spec-first/

# 2. 重新运行 setup
cd ~/.claude/skills/spec-first
./setup

# 3. 重启 Claude Code
```

---

### Q6: `/browse` 技能报错

**错误**: `browse binary not found`

**解决方案**:
```bash
# 1. 检查二进制文件
ls ~/.claude/skills/spec-first/browse/dist/browse

# 2. 如果不存在,重新构建
cd ~/.claude/skills/spec-first
bun run build

# 3. 验证
./browse/dist/browse --version
```

---

### Q7: `/qa` 无法连接到应用

**错误**: `Failed to connect to URL`

**解决方案**:
```bash
# 1. 确认应用正在运行
curl http://localhost:3000

# 2. 检查 URL 是否正确
/qa http://localhost:3000  # 不是 localhost:3000

# 3. 检查防火墙设置
```

---

### Q8: `/ship` 提示 "not on a feature branch"

**原因**: 你在 main/master 分支上。

**解决方案**:
```bash
# 1. 创建功能分支
git checkout -b feature/my-feature

# 2. 提交更改
git add -A
git commit -m "feat: my feature"

# 3. 运行 /ship
/ship
```

## 🎨 技能问题

### Q9: `/office-hours` 问太多问题,很烦

**原因**: 这正是它的价值 - 深度思考。

**解决方案**:
- **耐心回答**: 好的规划节省 10 倍实现时间
- **使用 escape hatch**: 如果真的想跳过,说 "skip questions"
- **快速模式**: 直接提供完整描述,减少来回

---

### Q10: `/review` 发现太多问题

**原因**: 代码质量需要改进。

**解决方案**:
```bash
# 1. 不要忽略问题
# 2. 分类处理:
#    - Critical/High: 必须修复
#    - Medium: 建议修复
#    - Low: 可选

# 3. 自动修复
/review --auto-fix
```

---

### Q11: `/qa` 报告太多 bug

**原因**: 测试覆盖率不足。

**解决方案**:
```bash
# 1. 查看报告
cat .spec-first/qa-reports/qa-report-*.md

# 2. 优先修复 Critical 和 High

# 3. 使用 /qa --quick 只测关键功能

# 4. 修复后重新测试
/qa
```

---

### Q12: `/canary` 一直告警

**原因**: 生产环境确实有问题。

**解决方案**:
```bash
# 1. 查看详细报告
cat .spec-first/canary-reports/canary-report-*.md

# 2. 分析问题:
#    - 控制台错误
#    - 性能退化
#    - 视觉变化

# 3. 如果是误报,调整阈值
# .spec-first/canary-config.json
```

## ⚙️ 配置问题

### Q13: 如何更改默认配置?

**解决方案**:
```bash
# 1. 编辑 CLAUDE.md
vim CLAUDE.md

# 2. 添加配置
## Spec-First Configuration
base_branch: main
test_command: bun test

# 3. 重启 Claude Code
```

---

### Q14: 如何配置部署?

**解决方案**:
```bash
# 运行配置技能
/setup-deploy

# 或手动配置
# 在 CLAUDE.md 中添加:
## Deploy Configuration
platform: fly
production_url: https://your-app.com
```

---

### Q15: 配置文件在哪里?

**答案**:
```
~/.spec-first/                  # 全局配置
  ├── config.json
  └── analytics/

your-project/
  ├── CLAUDE.md                 # 项目配置
  ├── DESIGN.md                 # 设计系统
  └── .spec-first/              # 项目数据
      ├── qa-reports/
      ├── canary-reports/
      └── benchmark-reports/
```

---

### Q16: 如何禁用分析/遥测?

**解决方案**:
```bash
# 编辑 ~/.spec-first/config.json
{
  "analytics": false,
  "telemetry": false
}

# 或设置环境变量
export SPEC_FIRST_ANALYTICS=false
export SPEC_FIRST_TELEMETRY=false
```

## ⚡ 性能问题

### Q17: 技能运行很慢

**原因**: 可能是网络或资源问题。

**解决方案**:
```bash
# 1. 检查网络
ping google.com

# 2. 检查资源占用
top

# 3. 使用快速模式
/qa --quick
/review --quick

# 4. 清理缓存
rm -rf ~/.spec-first/cache
```

---

### Q18: `/qa` 或 `/canary` 超时

**解决方案**:
```bash
# 增加超时时间
/qa --timeout 60000  # 60 秒

# 或在配置文件中设置
# .spec-first/qa-config.json
{
  "timeout": 60000
}
```

---

### Q19: 内存占用过高

**解决方案**:
```bash
# 1. 检查内存占用
ps aux | grep spec-first

# 2. 清理旧数据
rm -rf ~/.spec-first/analytics/*.old
rm -rf ~/.spec-first/sessions/*.old

# 3. 限制并发
# 不要同时运行多个 /qa 或 /canary
```

## 👥 团队协作问题

### Q20: 团队成员的技能版本不一致

**解决方案**:
```bash
# 1. 更新到最新版本
cd ~/.claude/skills/spec-first
git pull origin main
./setup

# 2. 项目中使用固定版本
# 在项目的 .claude/skills/spec-first/ 中提交
git add .claude/skills/spec-first
git commit -m "Update spec-first to vX.Y.Z"
```

---

### Q21: 如何共享配置?

**解决方案**:
```bash
# 1. 提交配置到 git
git add CLAUDE.md DESIGN.md .spec-first/

# 2. 团队成员拉取
git pull

# 3. 重新安装 (如果需要)
cd .claude/skills/spec-first && ./setup
```

---

### Q22: 如何统一团队的技能使用?

**解决方案**:
```markdown
# 在项目的 CLAUDE.md 中添加:

## Team Workflow

### Required Skills (所有 PR 必须通过)
- `/review` - 代码审查
- `/qa --standard` - QA 测试

### Optional Skills (根据需要)
- `/plan-ceo-review` - 大型功能
- `/codex review` - 复杂逻辑
```

---

### Q23: 如何处理技能冲突?

**场景**: 不同团队成员使用不同配置。

**解决方案**:
```bash
# 1. 统一配置
# 在项目中使用 .claude/skills/spec-first/

# 2. 不要使用全局安装
# 注释掉 ~/.claude/skills/spec-first/

# 3. 所有配置提交到 git
git add .claude/
```

## 🔄 更新和维护

### Q24: 如何更新 Spec-First?

**解决方案**:
```bash
# 方法 1: 自动更新
/spec-first-upgrade
```

---

### Q25: 更新后技能不工作

**解决方案**:
```bash
# 1. 清理缓存
rm -rf ~/.claude/skills/spec-first/node_modules
rm -rf ~/.claude/skills/spec-first/browse/dist

# 2. 重新构建
cd ~/.claude/skills/spec-first
bun install
bun run build

# 3. 重新运行 setup
./setup
```

---

```bash
cd ~/.claude/skills/spec-first

# 查看可用版本
git tag

# 切换到旧版本
git checkout v1.3.1.1
./setup
```
