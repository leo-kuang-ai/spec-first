# 配置指南

本指南介绍如何自定义和配置 Spec-First,以适应你的工作流程和偏好。

## 📁 配置文件结构

### 全局配置

位置: `~/.spec-first/`

```
~/.spec-first/
├── config.json              # 全局配置
├── analytics/               # 使用分析
│   └── skill-usage.jsonl
├── projects/                # 项目数据
│   └── {project-slug}/
│       ├── *-design-*.md    # 设计文档
│       ├── *-test-plan-*.md # 测试计划
│       └── reviews.jsonl    # 审查记录
└── sessions/                # 会话数据
```

### 项目配置

位置: 项目根目录

```
your-project/
├── CLAUDE.md                # Claude Code 配置
├── DESIGN.md                # 设计系统 (可选)
├── TODOS.md                 # 待办事项
├── .spec-first/             # 项目本地数据
│   ├── qa-reports/          # QA 报告
│   ├── canary-reports/      # 监控报告
│   └── benchmark-reports/   # 性能报告
└── .claude/
    └── skills/
        └── spec-first/      # 项目本地安装
```

## ⚙️ CLAUDE.md 配置

### 基础配置

在项目根目录的 `CLAUDE.md` 中添加:

```markdown
# 项目配置

## Spec-First 技能

本项目使用 Spec-First 进行开发。

### 浏览器交互

**重要**: 使用 `/browse` 技能进行所有浏览器交互,不要使用 `mcp__claude-in-chrome__*` 工具。

### 可用技能

- `/brainstorm` - 产品规划
- `/plan-ceo-review` - CEO 审查
- `/plan-eng-review` - 工程审查
- `/review` - 代码审查
- `/qa` - QA 测试
- `/ship` - 发布流程
- `/land-and-deploy` - 部署
- `/canary` - 监控
- `/benchmark` - 性能测试

### 故障排除

如果技能无法运行:
\`\`\`bash
cd .claude/skills/spec-first
./setup
\`\`\`
```

### 部署配置

添加部署配置:

```markdown
## Deploy Configuration

platform: fly
production_url: https://your-app.com
health_check: /health
deploy_command: fly deploy
deploy_status: fly status

## Deployment Checklist

1. Run tests: `bun test`
2. Build: `bun run build`
3. Deploy: `/land-and-deploy https://your-app.com`
```

### 测试配置

```markdown
## Test Commands

- Rails tests: `bin/test-lane`
- Vitest tests: `npm run test`
- E2E tests: `npm run test:e2e`

## Test Coverage

Minimum coverage: 80%

## Eval Suites

When these files change, run evals:
- `app/services/*_prompt_builder.rb`
- `config/system_prompts/*.txt`
```

### Git 工作流配置

```markdown
## Git Workflow

base_branch: master

## Commit Style

- Use conventional commits
- One logical change per commit
- Reference issues: #123

## Branch Naming

- Feature: feature/description
- Fix: fix/description
- Refactor: refactor/description
```

### QA 配置

在 `.spec-first/qa-config.json`:

```json
{
  "tiers": {
    "quick": ["critical", "high"],
    "standard": ["critical", "high", "medium"],
    "exhaustive": ["critical", "high", "medium", "low"]
  },
  "ignorePatterns": [
    "/admin/*",
    "/internal/*"
  ],
  "authRequired": ["/dashboard", "/settings"],
  "timeout": 30000
}
```

在 `.spec-first/canary-config.json`:

{

  "duration": 600,

## 🔧 环境变量

### 全局环境变量

在 `~/.bashrc` 或 `~/.zshrc`:

```bash
# Spec-First 配置
export SPEC_FIRST_DATA_DIR="$HOME/.spec-first"
export SPEC_FIRST_ANALYTICS=true
export SPEC_FIRST_TELEMETRY=true
```

### 项目环境变量

在 `.env`:

```bash
# 部署配置
DEPLOY_PLATFORM=fly
DEPLOY_PRODUCTION_URL=https://your-app.com
DEPLOY_HEALTH_CHECK=/health

# 测试配置
QA_BASE_URL=http://localhost:3000
QA_HEADLESS=true

# 监控配置
CANARY_SLACK_WEBHOOK=https://hooks.slack.com/...
```

## 📊 性能配置

### Bun 配置

`bunfig.toml`:

```toml
[install]
production = false

[test]
coverage = true
coverageThreshold = 0.8

[run]
# Preload spec-first binaries
preload = [".claude/skills/spec-first/browse/dist/browse"]
```

### Git Hooks

`.husky/pre-commit`:

```bash
#!/bin/sh
. "$(dirname "$0")/_/husky.sh"

# 运行 Spec-First 审查
/review --quick

# 运行快速测试
bun test
```

## 🔒 安全配置

### 安全策略

在项目根目录创建 `.spec-first/security.json`:

```json
{
  "protectedBranches": ["master", "production"],
  "requiredReviews": {
    "master": 1,
    "production": 2
  },
  "blockedCommands": [
    "DROP TABLE",
    "TRUNCATE",
    "DELETE FROM users"
  ],
  "freezeDefaults": {
    "production": true,
    "staging": false
  }
}
```

### 敏感数据处理

在 `.gitignore`:

```gitignore
# Spec-First 敏感数据
.spec-first/credentials/
.spec-first/*.key
.spec-first/*.pem
.spec-first/.env.local

# 分析数据 (可选)
.spec-first/analytics/
```

## 📱 团队协作配置

### 共享配置

在项目根目录:

```markdown
# CLAUDE.md

## Team Workflow

### 技能使用规范

1. **规划阶段**: 必须运行 `/brainstorm`
2. **审查阶段**: 所有 PR 必须通过 `/review`
3. **测试阶段**: 所有 PR 必须通过 `/qa`
4. **发布阶段**: 使用 `/ship` 自动化发布

### 分工

- 产品经理: `/brainstorm`, `/plan-ceo-review`
- 技术主管: `/plan-eng-review`, `/review`
- 开发者: `/investigate`, `/qa`
- QA: `/qa-only`, `/canary`
- 运维: `/land-and-deploy`, `/setup-deploy`

### 通知

- PR 创建: 自动通知 #dev-team
- 部署完成: 自动通知 #releases
- 监控告警: 自动通知 #incidents
```

## 🔄 配置管理

### 版本控制

将配置纳入版本控制:

```bash
# 提交配置
git add CLAUDE.md DESIGN.md .spec-first/*.json
git commit -m "Update spec-first configuration"
```

### 配置同步

团队成员同步配置:

```bash
# 拉取最新配置
git pull

# 重新安装 (如果 .claude/skills/spec-first 有更新)
cd .claude/skills/spec-first
./setup
```
