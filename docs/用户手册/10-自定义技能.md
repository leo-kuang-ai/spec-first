# 自定义技能

本指南教你如何创建自己的 Spec-First 技能。

## 🎯 概述

### 什么是技能?

技能是 Claude Code 的扩展,定义了特定的能力和工作流程。

**技能组成**:
- `SKILL.md.tmpl` - 技能模板文件
- `SKILL.md` - 生成的技能文件
- `bin/` - 可选的辅助脚本
- `hooks/` - 可选的钩子脚本

### 技能类型

1. **简单技能** - 仅文档,无脚本
2. **工具技能** - 包含辅助脚本
3. **钩子技能** - 带有事件钩子

## 🚀 快速开始

### 创建第一个技能

#### 1. 创建技能目录

```bash
cd ~/.claude/skills/spec-first
mkdir my-skill
cd my-skill
```

#### 2. 创建模板文件

创建 `SKILL.md.tmpl`:

```markdown
---
name: my-skill
version: 1.0.0
description: |
  My custom skill description. Use when asked to "do something".
allowed-tools:
  - Bash
  - Read
  - Write
---

{{PREAMBLE}}

# My Skill

You are a helpful assistant specialized in [domain].

## Instructions

1. Step 1: [description]
2. Step 2: [description]
3. Step 3: [description]

## Output

Describe what this skill produces.
```

#### 3. 生成技能文件

```bash
cd ~/.claude/skills/spec-first
bun run gen:skill-docs
```

#### 4. 测试技能

在 Claude Code 中运行:
```
/my-skill
```

## 📖 技能模板详解

### Frontmatter (元数据)

```yaml
---
name: skill-name                    # 技能名称 (必填)
version: 1.0.0                      # 版本号 (必填)
description: |                      # 描述 (必填)
  Multi-line description.
  Use when asked to "keyword".
allowed-tools:                      # 允许的工具
  - Bash
  - Read
  - Write
  - Edit
  - Grep
  - Glob
  - AskUserQuestion
  - WebSearch
benefits-from: [other-skill]        # 依赖的其他技能 (可选)
hooks:                              # 钩子 (可选)
  PreToolUse:
    - matcher: "Edit"
      hooks:
        - type: command
          command: "script.sh"
---
```

### 占位符

模板支持以下占位符:

- `{{PREAMBLE}}` - 标准前言
- `{{BROWSE_SETUP}}` - 浏览器设置
- `{{BASE_BRANCH_DETECT}}` - 基础分支检测
- `{{TEST_BOOTSTRAP}}` - 测试框架引导
- `{{BENEFITS_FROM}}` - 依赖技能处理

**使用示例**:

```markdown
{{PREAMBLE}}

{{BROWSE_SETUP}}

# My Skill

Skill content here...
```

## 🛠️ 高级功能

### 1. 使用 Bash 脚本

**创建脚本**:

```bash
mkdir bin
cat > bin/my-helper.sh << 'EOF'
#!/bin/bash
echo "Helper script output"
EOF

chmod +x bin/my-helper.sh
```

**在技能中调用**:

```markdown
## Step 1: Run Helper

```bash
~/.claude/skills/spec-first/my-skill/bin/my-helper.sh
```
```

### 2. 添加钩子

**创建钩子脚本**:

```bash
mkdir -p hooks
cat > hooks/pre-edit.sh << 'EOF'
#!/bin/bash
# Read tool input from stdin
read -r input

# Check something
if echo "$input" | grep -q "production"; then
  echo "Warning: Editing production files"
fi

# Allow the operation
echo '{"permissionDecision": "allow"}'
EOF

chmod +x hooks/pre-edit.sh
```

**在模板中声明**:

```yaml
hooks:
  PreToolUse:
    - matcher: "Edit"
      hooks:
        - type: command
          command: "bash ${CLAUDE_SKILL_DIR}/hooks/pre-edit.sh"
          statusMessage: "Checking edit..."
```

### 3. 使用状态目录

```markdown
## Save State

```bash
STATE_DIR="${CLAUDE_PLUGIN_DATA:-$HOME/.spec-first}"
mkdir -p "$STATE_DIR/my-skill"
echo "data" > "$STATE_DIR/my-skill/state.txt"
```

## Read State

```bash
STATE_DIR="${CLAUDE_PLUGIN_DATA:-$HOME/.spec-first}"
cat "$STATE_DIR/my-skill/state.txt" 2>/dev/null || echo "No state found"
```
```

### 4. 集成其他技能

**声明依赖**:

```yaml
benefits-from: [brainstorm, plan-eng-review]
```

**使用依赖**:

```markdown
{{BENEFITS_FROM}}

This skill builds on /brainstorm and /plan-eng-review.
```

## 📝 最佳实践

### 1. 命名规范

- 使用小写字母和连字符
- 描述性强: `code-review`, 不是 `cr`
- 避免动词: `review`, 不是 `review-code`

### 2. 描述模板

```yaml
description: |
  One-line summary. Use when asked to "trigger phrase 1",
  "trigger phrase 2", or "trigger phrase 3".
  Proactively suggest when [condition].
```

### 3. 工具选择

只请求必需的工具:

```yaml
# ✅ 好 - 只请求需要的
allowed-tools:
  - Bash
  - Read
  - Grep

# ❌ 避免 - 请求所有工具
allowed-tools: all
```

### 4. 结构化指令

```markdown
# ✅ 好 - 清晰的步骤

## Phase 1: Analysis

1. Read the file
2. Analyze patterns
3. Generate report

## Phase 2: Action

1. Make changes
2. Verify results

---

# ❌ 避免 - 模糊的指令

Just do it when needed.
```

### 5. 错误处理

```markdown
## Step 1: Check Prerequisites

```bash
# Check if file exists
if [ ! -f "package.json" ]; then
  echo "Error: package.json not found"
  echo "Run this in a Node.js project root"
  exit 1
fi
```
```

## 📦 分发技能

### 方法 1: 添加到 Spec-First

1. Fork Spec-First 仓库
2. 添加技能到 `skills/` 目录
3. 提交 Pull Request

### 方法 2: 独立分发

```bash
# 1. 创建独立仓库
mkdir my-spec-first-skills
cd my-spec-first-skills
git init

# 2. 添加技能
cp -R ~/.claude/skills/spec-first/my-skill .

# 3. 添加 README
cat > README.md << EOF
# My Spec-First Skills

## Installation

\`\`\`bash
git clone https://github.com/user/my-spec-first-skills.git ~/.claude/skills/my-skills
cd ~/.claude/skills/my-skills
./setup
\`\`\`

## Skills

- \`/my-skill\` - Description
EOF

# 4. 发布
git add .
git commit -m "Add my-skill"
git remote add origin https://github.com/user/my-spec-first-skills.git
git push -u origin master
```

## 🎓 进阶示例

### 示例 1: 代码生成器

```markdown
---
name: gen-component
version: 1.0.0
description: |
  Generate React components from templates. Use when asked to
  "create component", "generate component", or "new component".
allowed-tools:
  - Bash
  - Read
  - Write
  - AskUserQuestion
---

{{PREAMBLE}}

# Component Generator

Generate React components with best practices.

## Step 1: Gather Requirements

Ask via AskUserQuestion:
- Component name
- Type (functional/class)
- Features (hooks, context, etc.)

## Step 2: Generate Component

```bash
COMPONENT_NAME="<user-input>"
mkdir -p src/components/$COMPONENT_NAME
```

Write to `src/components/$COMPONENT_NAME/$COMPONENT_NAME.tsx`:

\`\`\`typescript
import React from 'react';

interface {{COMPONENT_NAME}}Props {
  // Props here
}

export const {{COMPONENT_NAME}}: React.FC<{{COMPONENT_NAME}}Props> = (props) => {
  return (
    <div className="{{COMPONENT_NAME | kebab-case}}">
      {/* Component content */}
    </div>
  );
};
\`\`\`

## Step 3: Generate Test

Write to `src/components/$COMPONENT_NAME/$COMPONENT_NAME.test.tsx`:

\`\`\`typescript
import { render } from '@testing-library/react';
import { {{COMPONENT_NAME}} } from './{{COMPONENT_NAME}}';

describe('{{COMPONENT_NAME}}', () => {
  it('renders without crashing', () => {
    render(<{{COMPONENT_NAME}} />);
  });
});
\`\`\`

## Step 4: Generate Index

Write to `src/components/$COMPONENT_NAME/index.ts`:

\`\`\`typescript
export { {{COMPONENT_NAME}} } from './{{COMPONENT_NAME}}';
export type { {{COMPONENT_NAME}}Props } from './{{COMPONENT_NAME}}';
\`\`\`

Component generated successfully!
```

### 示例 2: 数据库迁移助手

```markdown
---
name: db-migrate
version: 1.0.0
description: |
  Generate and run database migrations. Use when asked to
  "create migration", "add column", or "migrate database".
allowed-tools:
  - Bash
  - Read
  - Write
---

{{PREAMBLE}}

# Database Migration Helper

Generate Rails-style migrations.

## Step 1: Parse Request

Extract from user request:
- Table name
- Action (add/remove/change)
- Columns and types

## Step 2: Generate Migration

```bash
TIMESTAMP=$(date +%Y%m%d%H%M%S)
MIGRATION_FILE="db/migrate/${TIMESTAMP}_<action>_<table>.rb"
mkdir -p db/migrate
```

Write migration file:

\`\`\`ruby
class <Action><Table> < ActiveRecord::Migration[7.0]
  def change
    # Migration code here
  end
end
\`\`\`

## Step 3: Review Migration

Display the generated migration for review.

## Step 4: Run Migration (if approved)

```bash
rails db:migrate
rails db:migrate:status
```

Migration complete!
```
