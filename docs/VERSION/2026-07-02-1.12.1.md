## 摘要

`spec-first@1.12.1` 在保持 CLI 与 runtime 对外行为完全兼容的前提下,以**需求工作流(PRD)工程化**为核心完成一次深度强化,并同步提升规划、执行、代码审查、调试与知识沉淀等核心链路的稳定性与可治理性。本版将 `write-tasks` 正式升级为公开工作流,新增需求写前与就绪把关能力,并修复第三方依赖的已知安全漏洞。本版为向后兼容的 patch,不含破坏性变更,可从 `1.12.0` 直接升级,无需迁移。

## 亮点

### 需求工作流(PRD)升级为可治理的工程闭环

本版投入最集中的部分:需求环节从一次性对话转变为具备写前把关、决策留痕与并发安全的工程流程。

- **写前质询:** 在需求写入前基于多类信号强制澄清关键歧义与缺口,从源头降低"范围未定即开工"导致的返工。
- **决策留痕(Decision Card):** 将关键取舍与责任人确认固化为可验证的决策产物,并在写入前执行 dry-run 校验与模板合规检查。
- **确认真实性校验:** 引入责任人确认真实性闸,避免将"已确认"声明直接视为可信事实。
- **就绪与并发保障:** 收窄就绪校验的工作树扫描边界,加固输入路径处理,支持多会话并发,并修复合法收口被误阻断的问题。
- **确定性执行架构:** 采用三阶段执行流程并强制关键检查,使每个关键出口达标方可通过、否则阻断,而非依赖模型自觉。

### 公开入口扩展:write-tasks 转正

`write-tasks` 由内部能力正式升级为公开工作流,补齐"计划已定稿、但直接执行风险较高或上下文负载过重"时的派生任务层。

- 可将定稿计划编译为**可选**的派生任务包,或在执行前完成任务包校验;计划始终为单一真源,任务包为派生且可选。
- 入口:`spec-write-tasks`(Claude Code)、`spec-write-tasks`(Codex)。

### 核心链路质量同步强化

- **规划(spec-plan):** 新增企业级计划评审与复用分析引用文档,强化计划深度、复用优先与反过度设计判断。
- **执行(spec-work):** 新增"最小化 + 架构契合预检"作为落地前的注意力检查(三项最小化 + 两项架构契合),要求架构决策引用直接证据而非泛化最佳实践;当改动涉及计划或任务未授权的新公共契约、跨模块抽象或 schema/runtime/config 面时,中止并回退至规划或任务包重生成。
- **执行(spec-work):** 任务包执行前引入就绪校验,区分"本次生成""已复核""未复核"三种状态,对证据不足或已过期者先路由至审查或重生成,再进入执行。
- **代码审查(spec-code-review):** 引入边界图评估、未跟踪产物契约与最小化预检,使审查更聚焦真实影响面。
- **调试(spec-debug):** 强化反馈环纪律,将性能回归列为一等关注项,并提供人在环(HITL)循环模板与更准确的修复接缝判断。
- **知识沉淀(spec-compound):** 集成领域建模(domain-modeling)捕获,提升可复用经验的结构化程度。
- **Skill 编写(spec-write-skill):** 对 skill 编写工作流进行健壮性与稳定性加固,使新建、改写或迁移 source skill 时产出更精简、更可治理的补丁。

### 路由与触发精度提升

- 对核心链路多个 skill 的触发条件进行系统性校准,使路由更贴合真实意图并减少误触发。
- 将入口治理(using-spec-first)收敛为以功能地图为主,治理细则下沉至引用文档,并补充调度边界与范围守护说明,降低进入错误工作流的概率。

### 可验证性与治理基线

- 为多个工作流补充评估用例(evals),以可执行用例提升行为回归的可验证性,而非仅依赖文字约定。
- 新增 Agent 生命周期目录契约,统一 agent 能力与边界的说明基线;治理入口文档对齐最新角色契约。

### 上手与理解体验升级

- README 重构为**双读者渐进披露**结构,入口表收敛至研发主链路,兼顾新用户与既有用户。
- 新增模拟 CLI 工作流动画图,约 90 秒即可完整了解从安装、初始化、runtime setup 到需求、规划、任务拆分、执行、审查、知识沉淀的端到端闭环,以及产物在仓库中的证据链。

## 新增

- `write-tasks` 公开工作流入口,支持计划到任务包的编译与执行前校验。
- 需求工作流的写前把关与就绪把关能力,随宿主初始化投递,默认纳入 gitignore。
- 规划、调试、知识沉淀等工作流的专题引用文档:企业级计划评审、复用分析、性能回归、领域建模捕获、调度边界与范围守护。
- 多个工作流的评估用例(evals),提升行为回归的可验证性。
- Agent 生命周期目录契约,统一 agent 能力与边界的说明基线。

## 修复

- 收口需求工作流多项稳定性问题,涵盖就绪校验边界、输入路径安全、并发闸口与执行流程一致性,并修复合法收口被误阻断的情况。
- 修复 Windows 平台 npm 安装矩阵的命令 shim 引用问题。
- 修复第三方依赖 `js-yaml` 与 `@babel/core` 的已知安全漏洞。

## 升级注意事项

- 本版为向后兼容的 patch,不含破坏性变更,可从 `1.12.0` 直接升级,无需任何迁移步骤;CLI 命令与 runtime 对外行为均无变化。
- 升级后建议运行一次 `spec-first update` 检查 runtime 新鲜度;如需重建宿主 runtime 资产,运行 `spec-first init`。
- 本版工作流(尤其是需求工作流)改动较多,完整技术明细请参阅仓库 `CHANGELOG.md` 与 `git log v1.12.0..v1.12.1`。
