## Summary

`spec-first@1.12.1` delivers a focused strengthening of the requirements (PRD) workflow into a governable engineering loop, while raising the stability and governability of the planning, execution, code-review, debugging, and knowledge-capture chains. This release promotes `write-tasks` to a public workflow, adds pre-write and readiness guards for the requirements workflow, and fixes known security vulnerabilities in third-party dependencies. It is a backward-compatible patch with no breaking changes and can be upgraded directly from `1.12.0` with no migration.

## Highlights

### The requirements (PRD) workflow becomes a governable engineering loop

The largest investment in this release. The requirements phase is no longer a one-shot conversation, but a workflow with gating, traceability, and concurrency safety:

- **Pre-write grilling:** ambiguities and gaps are clarified before requirements are written, triggered by several signals, cutting rework that comes from starting work before scope is settled.
- **Decision traceability (Decision Card):** key trade-offs and owner confirmations are captured as a verifiable decision artifact, with a dry-run lint and template compliance check before write.
- **Owner-confirmation authenticity check:** an authenticity gate prevents treating an "I confirmed this" claim as confirmed truth.
- **Readiness and concurrency safety:** the readiness check's worktree scan boundary is narrowed, input-path handling is hardened, multi-session concurrency is supported, and a case where a legitimate closeout was wrongly blocked is fixed.
- **Deterministic execution architecture:** a three-phase flow enforces its critical checks so each key exit either meets its bar or blocks, instead of relying on the model's discretion.

### New public entrypoint: write-tasks

`write-tasks` is promoted from an internal capability to a public workflow, filling the derived-task layer for when a plan is settled but direct execution is risky or context-heavy:

- It compiles a settled plan into an **optional** derived task pack, or validates an existing task pack before execution; the plan stays the single source of truth and the task pack is derived and optional.
- Entrypoints: `/spec:write-tasks` (Claude Code) and `$spec-write-tasks` (Codex).

### Core-chain quality improvements

- **Planning (spec-plan):** adds enterprise-grade plan review and reuse-analysis references, strengthening plan depth, reuse-first thinking, and over-engineering avoidance.
- **Execution (spec-work):** adds a Minimality + Architecture Fit preflight that requires direct evidence before introducing any durable surface (dependency, file, abstraction, public contract, or schema/runtime/config surface), and stops to route back to planning when an unauthorized new surface is required.
- **Execution (spec-work):** validates a task pack before running it, distinguishing packs generated in the current run from previously reviewed or unchecked ones, and routing stale or unverifiable packs back to review or regeneration.
- **Code review (spec-code-review):** adds boundary-graph evaluation, an untracked-artifact contract, and a minimality preflight, keeping review focused on real impact.
- **Debugging (spec-debug):** strengthens feedback-loop discipline, treats performance regression as a first-class concern, and adds a human-in-the-loop (HITL) loop template plus sharper fix-seam judgment.
- **Knowledge capture (spec-compound):** integrates domain-modeling capture so reusable learnings are more structured.
- **Skill authoring (spec-write-skill):** robustness and stability hardening across the authoring workflow, so writing, revising, or migrating a source skill produces cleaner, more governable patches.

### Routing and trigger precision

- Trigger conditions across several core-chain skills were systematically polished, so routing matches real intent with fewer false triggers.
- Entry governance (using-spec-first) is condensed into a capability-map-first shape, with governance detail moved into references and added dispatch-boundary and scope-guard guidance, lowering the chance of entering the wrong workflow.

### Verifiability and governance baseline

- Evaluation cases (evals) were added for several workflows, improving behavioral-regression verifiability instead of relying on prose conventions alone.
- A new agent lifecycle catalog contract unifies the baseline for describing agent capabilities and boundaries; governance entry docs are aligned with the latest role contract.

### Onboarding and comprehension

- The README is restructured into a dual-reader progressive-disclosure format, with the entrypoint table condensed to the main engineering chain so new and existing users each find what they need.
- A simulated CLI workflow animation is added so the end-to-end loop — from install, init, and runtime setup through requirements, planning, task splitting, execution, review, and knowledge capture — plus the repo-local artifact trail, can be understood in about 90 seconds.

## Added

- `write-tasks` public workflow entrypoint, supporting plan-to-task-pack compilation and pre-execution validation.
- Pre-write and readiness guards for the requirements workflow, delivered by host initialization and gitignored by default.
- Topic references for the planning, debugging, and knowledge-capture workflows: enterprise plan review, reuse analysis, performance regression, domain-model capture, dispatch boundaries, and scope guards.
- Evaluation cases (evals) for several workflows, improving behavioral-regression verifiability.
- An agent lifecycle catalog contract that unifies the baseline for agent capabilities and boundaries.

## Fixed

- Closed out several requirements-workflow stability issues, covering readiness-check boundaries, input-path safety, concurrency gating, and execution-flow consistency, including a case where a legitimate closeout was wrongly blocked.
- Fixed a command-shim reference issue in the Windows npm install matrix.
- Fixed known security vulnerabilities in the third-party dependencies `js-yaml` and `@babel/core`.

## Upgrade Notes

- This is a backward-compatible patch with no breaking changes; it can be upgraded directly from `1.12.0` with no migration steps, and CLI commands and runtime behavior are unchanged.
- After upgrading, run `spec-first update` once to check runtime freshness; run `spec-first init` if you need to rebuild host runtime assets.
- This release changes many workflows (especially the requirements workflow); for the full technical detail, see the repository `CHANGELOG.md` and `git log v1.12.0..v1.12.1`.
