## 摘要

`spec-first@1.12.1` 在保持 CLI 与 runtime 对外行为完全兼容的前提下,完成了一次以**需求工作流(PRD)工程化**为核心的深度强化,并同步提升了规划、代码审查、调试与知识沉淀等核心链路的稳定性与可治理性。本版将 `write-tasks` 正式升级为公开工作流,新增需求写前与就绪把关能力,并修复了第三方依赖的已知安全漏洞。本版为向后兼容的 patch,无破坏性变更,可从 `1.12.0` 直接升级,无需迁移。

## 亮点

### 需求工作流(PRD)升级为可治理的工程闭环

本版最大的一块投入。需求环节不再是一次性对话,而是一条有把关、有留痕、可并发的工程流程:

- **写前质询(grill-before-write):** 需求落盘前先强制澄清关键歧义与缺口,由多个信号触发进入质询,从源头减少"范围未定即开工"的返工。
- **决策留痕(Decision Card):** 关键取舍与责任人确认沉淀为可验证的决策产物,并在写入前执行 dry-run 校验与合规模板检查。
- **确认真实性把关:** 引入责任人确认真实性闸,杜绝将"我已确认"这类声明直接当作可信事实。
- **就绪与并发保障:** 收窄就绪校验的工作树扫描边界、加固输入路径安全、支持多会话并发,并修复合法收口曾被误阻断的问题。
- **确定性执行架构:** 采用三阶段流程,强制关键检查闸与双确定性出口不变量,让工作流的关键出口"要么达标要么阻断",而非全凭模型自觉。

### 公开入口扩展:write-tasks 转正

`write-tasks` 由内部能力正式升级为公开工作流,填补了"计划已定稿、但直接执行风险高或上下文过载"时的派生任务层:

- 可将定稿计划编译为**可选**的派生任务包,或在执行前完成任务包的确定性校验;计划始终是单一真源,任务包是派生且可选的。
- 入口:`/spec:write-tasks`(Claude Code)、`$spec-write-tasks`(Codex)。

### 核心链路质量同步强化

- **规划(spec-plan):** 新增企业级计划评审与复用分析引用文档,强化计划深度、复用优先与反过度设计判断。
- **执行(spec-work):** 新增"最小化 + 架构契合预检"——在引入依赖、文件、抽象、公共契约、schema/runtime/config 面等 durable surface 前,先做最小化与架构契合检查并要求直接证据,未授权的新面会停下并回退规划;同时对任务包引入语义姿态入口校验,区分"本次生成"与"已复核/未复核",证据不足或过期即先路由到审查或重生成,再配合执行期复用复检与最小化技术债延迟跟进,让"按计划落地"更贴合真实影响面、更防越权与过度实现。
- **代码审查(spec-code-review):** 引入边界图评估、未跟踪产物契约与最小化预检,让审查更聚焦真实影响面。
- **调试(spec-debug):** 强化反馈环纪律,将性能回归纳入一等公民,并提供人在环(HITL)循环模板与更准确的修复接缝判断。
- **知识沉淀(spec-compound):** 集成领域建模(domain-modeling)捕获,让可复用经验的结构化程度更高。

### 路由与触发精度提升

- 核心链路多个 skill 的触发条件做了系统性打磨,路由更贴合真实意图、更少误触发。
- 入口治理(using-spec-first)收敛为"功能地图为主",治理细则下沉到引用文档,并补充调度边界与范围守护说明,降低误入错误工作流的概率。

### 可验证性与治理基线

- 为多个工作流补充评估用例(evals),提升行为回归的可验证性,而不是仅靠 prose 约定。
- 新增 Agent 生命周期目录契约,统一 agent 能力与边界的说明基线;治理入口文档对齐最新角色契约。

### 上手与理解体验升级

- README 重构为**双读者渐进披露**结构,入口表收敛为研发主链路,新老用户各取所需。
- 新增模拟 CLI 工作流动画图,约 90 秒即可看懂从安装、初始化、runtime setup 到需求、规划、任务拆分、执行、审查、知识沉淀的端到端闭环,以及产物在仓库中的证据链。

## 新增

- `write-tasks` 公开工作流入口,支持计划到任务包的编译与执行前校验。
- 需求工作流的写前把关与就绪把关能力,随宿主初始化投递,默认纳入 gitignore。
- 规划、调试、知识沉淀等工作流的专题引用文档:企业级计划评审、复用分析、性能回归、领域建模捕获、调度边界与范围守护。
- 多个工作流补充评估用例(evals),提升行为回归的可验证性。
- Agent 生命周期目录契约,统一 agent 能力与边界的说明基线。

## 修复

- 收口需求工作流多项稳定性问题,涵盖就绪校验边界、输入路径安全、并发闸口与执行流程一致性,并修复合法收口曾被误阻断的情况。
- 修复 Windows 平台 npm 安装矩阵的命令 shim 引用问题。
- 修复第三方依赖 `js-yaml` 与 `@babel/core` 的已知安全漏洞。

## 升级注意事项

- 本版为向后兼容的 patch,不含破坏性变更,可从 `1.12.0` 直接升级,无需任何迁移步骤;CLI 命令与 runtime 对外行为均无变化。
- 升级后建议运行一次 `spec-first update` 检查 runtime 新鲜度;如需重建宿主 runtime 资产,运行 `spec-first init`。
- 本版工作流(尤其是需求工作流)改动较多,完整技术明细请参阅仓库 `CHANGELOG.md` 与 `git log v1.12.0..v1.12.1`。
