## 摘要

`spec-first@1.12.1` 是继 `v1.12.0` 之后累积的一次稳定性与体验强化版本。重点是需求工作流（PRD）的健壮性大幅加固、`write-tasks` 正式成为公开 workflow，以及调试、知识沉淀、代码审查、执行等核心链路的打磨。本版未改变 CLI 与 runtime 的对外行为，是一次可安全直接升级的 patch。

## 亮点

- 需求工作流（PRD）写前把关更严、决策留痕、多会话并发更安全，减少"需求没定清就开工"的返工。
- `write-tasks` 从内部能力转正为公开 workflow，可直接用 `/spec:write-tasks`（Claude Code）或 `$spec-write-tasks`（Codex）把已定稿计划拆成可执行任务包。
- 核心链路 skill 的触发条件做了精度打磨，路由更贴合意图、更少误触发。
- README 重排为双读者渐进披露结构，并新增模拟 CLI workflow 动画图，90 秒即可看懂端到端研发闭环。

## 新增

- `write-tasks` 公开 workflow：把定稿计划编译成可选的派生任务包，或在执行前校验已有任务包，计划始终是单一真源。
- 需求工作流引入写前把关与决策卡产物，明确记录关键取舍与责任人确认。
- 调试工作流把性能回归纳入一等公民，并强化反馈环纪律与修复接缝判断。
- 知识沉淀工作流支持领域建模（domain-modeling）捕获。
- 代码审查工作流引入边界图评估与未跟踪产物契约、最小化预检。

## 修复

- 收口需求工作流多项稳定性问题，包括就绪校验边界、输入路径安全、并发闸口与执行流程一致性。
- 修复 Windows 下 npm 安装矩阵的命令 shim 引用问题。
- 修复第三方依赖的已知安全漏洞（`js-yaml`、`@babel/core`）。

## 升级注意事项

- 本版为 patch，无破坏性变更，可从 `1.12.0` 直接升级，无需迁移步骤。
- 升级后建议运行一次 `spec-first update` 检查 runtime freshness；如需重建宿主 runtime 资产，运行 `spec-first init`。
