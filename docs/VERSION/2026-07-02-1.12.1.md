## 摘要

`spec-first@1.12.1` 在保持 CLI 与 runtime 对外行为完全兼容的前提下,完成了一次以**需求工作流(PRD)工程化**为核心的深度强化,并同步提升了规划、代码审查、调试与知识沉淀等核心链路的稳定性与可治理性。本版将 `write-tasks` 正式升级为公开工作流,新增需求写前与就绪把关能力,并修复了第三方依赖的已知安全漏洞。本版为向后兼容的 patch,无破坏性变更,可从 `1.12.0` 直接升级,无需迁移。

## 亮点

- **需求工作流从对话升级为工程闭环:** 需求在落盘前先经过写前质询,关键取舍与责任人确认沉淀为可验证的决策产物,并支持多会话并发,显著减少"范围未定即开工"导致的返工。
- **write-tasks 正式转为公开工作流:** 可将定稿计划编译为可选的派生任务包,或在执行前完成任务包校验,计划始终保持为单一真源;入口为 `/spec:write-tasks`(Claude Code)与 `$spec-write-tasks`(Codex)。
- **核心链路同步强化:** 规划新增企业级评审与复用分析,代码审查引入边界评估与最小化预检,调试将性能回归纳入一等公民,知识沉淀支持领域建模捕获。
- **上手体验升级:** README 重构为双读者渐进披露结构,并新增模拟 CLI 工作流动画图,约 90 秒即可理解从安装、初始化到需求、规划、执行、审查、知识沉淀的完整研发闭环。

## 新增

- `write-tasks` 公开工作流入口,支持计划到任务包的编译与执行前校验。
- 需求工作流的写前把关与就绪把关能力,随宿主初始化投递,默认纳入 gitignore。
- 规划、调试、知识沉淀等工作流的专题引用文档:企业级计划评审、复用分析、性能回归、领域建模捕获、调度边界与范围守护。
- 多个工作流补充评估用例(evals),提升行为回归的可验证性。
- Agent 生命周期目录契约,统一 agent 能力与边界的说明基线。

## 修复

- 收口需求工作流多项稳定性问题,涵盖就绪校验边界、输入路径安全、并发闸口与执行流程一致性,并修复合法收口曾被误阻断的情况。
- 修复 Windows 平台 npm 安装矩阵的命令 shim 引用问题。
- 修复第三方依赖 `js-yaml` 与 `@babel/core` 的已知安全漏洞。

## 升级注意事项

- 本版为向后兼容的 patch,不含破坏性变更,可从 `1.12.0` 直接升级,无需任何迁移步骤;CLI 命令与 runtime 对外行为均无变化。
- 升级后建议运行一次 `spec-first update` 检查 runtime 新鲜度;如需重建宿主 runtime 资产,运行 `spec-first init`。
- 本版工作流(尤其是需求工作流)改动较多,完整技术明细请参阅仓库 `CHANGELOG.md` 与 `git log v1.12.0..v1.12.1`。
