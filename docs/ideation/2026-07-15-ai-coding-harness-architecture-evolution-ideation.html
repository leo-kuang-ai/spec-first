Grounding Context

Codebase Context

项目已经拥有较完整的 Codebase → Spec → Plan → Tasks → Code → Review → Knowledge artifact 链、确定性 contract、五宿主 source/runtime 投射与 evidence 基础。真正的结构性缺口不在“有没有机制”，而在四件事：真实采用和 field outcome 尚未测量；material claim 尚未稳定贯穿 evidence、verification 与 outcome；generated runtime 不等于真实 host invocation；知识失效边界仍主要依赖 prose 约定。

业界趋势进一步压缩了项目应拥有的边界：宿主正在吸收 agent loop、session、sandbox、parallelism、trace、resume 与异步任务。OpenAI 强调 repo 可读性、结构测试和运行反馈；Anthropic 强调可恢复 artifact、显式 done/verification、JIT context 与 session/harness/sandbox 解耦。由此推导，spec-first 的长期护城河不是通用 agent runtime，而是项目拥有的 intent、claim/evidence、跨宿主语义与可失效知识。

第一性原理：如果一个机制不能缩短“正确意图形成可信结果”的时间，不能降低人工纠正/集成背压，也不能提高结果可证伪性，那么它即使增加了 agent、trace、artifact 或测试，也不构成架构进步。

外部依据：OpenAI Harness Engineering、Anthropic Context Engineering、Long-running Agent Harnesses、Agent Evals、MCP Tasks Extension 与 A2A 1.0。

1. Trusted Change Observatory

Experiment置信度 88%复杂度 Low

Description：选择 5–10 个明确 opt-in 的真实任务，人工记录 intent accepted、claim-scoped verification、owner trusted、人工修正、等待、reopen/rollback 与观察窗后的 field outcome。它不是 telemetry 平台，也不从 trace 静默推导价值；目标是第一次让 TTC 与 quality-adjusted throughput 进入架构决策。

Axis
Evaluation 与价值兑现
Basis
direct: README.md:196-206 明确现有机制不是 measured adoption-outcome claims；评估 dossier 证实 TTC、人工负担、field outcome 没有持续观测。external: OpenAI/Anthropic 的 agent eval 实践要求 transcript 与 outcome 分离、多 trial、多 grader。
Rationale
没有真实价值基线，任何新增 contract 都无法证明比删除更好。这是后续 Adopt、Thin、Retire 的共同度量地板。
Downsides
需要 owner 授权、隐私/脱敏和人工裁决；小样本不能用于营销式普遍结论。若数据不改变任何决策，应停止收集。
Boundary
先用分析文档与现有 run artifact，不新增事件 schema；预先声明停止条件、数据保留期和不得作为 outcome 代理的字段。

2. Semantic Host Conformance Pack

Wrap置信度 84%复杂度 Medium

Description：选一个 material workflow 与两个可实际运行的宿主，用 3–5 个协议中立黑盒 canary 验证 entry discovery、invocation、source/runtime authority、mutation gate、handoff 与 degraded 表达。每次结果只声明特定 host/version/fixture 下的 supported、lossy、degraded 与 expiry，不把 generated files 当行为支持。

Axis
Protocol、Knowledge 与跨宿主治理
Basis
direct: getSupportedPlatforms() 只证明 adapter 注册；README.zh-CN.md:16-18,95-97 明确 Cursor 尚未验证 discovery/invocation。external: MCP Tasks 仍实验，A2A 区分 task artifact 与 transport，支持 canonical semantics 与 adapter 解耦。
Rationale
它把“文件投射成功”与“宿主语义可依赖”分开，允许诚实地发布 lossy/degraded，同时避免追求 feature parity 或重建通用 orchestrator。
Downsides
全宿主 × 全版本矩阵会迅速变脆；canary 只能证明被测行为，不能推出宿主整体 fidelity。
Boundary
只维护会改变 mutation、verification、handoff 或 promotion claim 的 material canary；宿主提供等价 conformance fact 时删除 wrapper。

3. Counterfactual Harness Thinning

Thin置信度 82%复杂度 Low

Description：把大型 SKILL.md、重复治理 prose 与 rendering contract 当成需要证明存在价值的成本。选择一个热路径，删除一段重复上下文或抽取共享 source，再用代表性 fresh-source A/B 对比 decision quality、evidence coverage 与上下文体积；结果允许恢复，不建 Context MEL、Lease registry 或新预算 schema。

Axis
Context 与 Harness 瘦身
Basis
direct: 当前 spec-plan、spec-code-review 入口超过 800 行，多套 HTML rendering contract 完整复制；仓库已有 Front Controller、Triggered References 与 fresh-source eval 方法。external: Anthropic context engineering 指向 JIT retrieval 与 compaction。
Rationale
这项收益最确定：减少固定 token 税、source drift 和多宿主投射成本，同时不创造新 runtime。真正的创新是让每段默认上下文接受可撤销的因果检验。
Downsides
当前尚未量化 token/wall-time 成本；一次 A/B 不能证明所有模型与任务分布。过度抽取共享 source 也可能损害 skill-local 可移植性。
Boundary
先删重复治理 prose 或一个 rendering copy；若 evidence/decision quality 下降立即恢复。它是一种持续删减方法，不是可发布的新产品能力。

4. Failure-to-Eval Flywheel

Experiment置信度 75%复杂度 Medium

Description：把 owner-confirmed 的 reopen、人工大改、review escape、rollback 或 abandon 转为 3 个脱敏 task archetype，复用现有 eval/scorecard 做 baseline/candidate 多 trial 与盲 outcome grading。只有真实失败被后续回归实际消费，才继续扩充样本。

Axis
Evaluation 与价值兑现
Basis
direct: 项目已有 deterministic fixtures、局部 fresh-source A/B 和 structured closeout，却缺真实返工样本与 field outcome。external: OpenAI、METR、SWE-rebench 强调任务分布、freshness、harness/model/version 与多次运行。
Rationale
真实失败是最稀缺的 eval 数据。每个被转化的失败都能让未来 harness 变更围绕用户真正付过的成本回归，而非围绕易写断言优化。
Downsides
当前还没有 confirmed 样本供给证据；脱敏、授权、grader 漂移与任务陈旧成本不可忽略。
Boundary
从 3 个案例开始，不自动采集 transcript，不建 benchmark 平台；样本不再影响设计决策时退役或重采样。
5

5. Material Claim Join Pilot

Experiment置信度 72%复杂度 Medium

Description：不要建设统一 Trust BOM 或 evidence graph。先在 5–10 个 completion/review 样本中，用临时 sidecar 手工关联一个 material claim、现有 evidence refs、support/refute、scope 与 freshness，验证跨 artifact join 是否真的减少重复回读或漏证。

Axis
Evidence 与可信闭环
Basis
direct: verification evidence 具有 gate_ids、status、artifact 与时间，却没有 material claim identity 或 support/refute 关系；spec_id 明确不是中央状态/进度键。reasoned: claim 是证据充分性判断的最小语义单位，但必须先证明共享 join key 有真实 consumer。
Rationale
它可能补上 evidence → verification → outcome 的关键连接，又通过 sidecar 实验避免一次性迁移所有 workflow schema。
Downsides
极易演化成第二套 evidence contract、状态图与字段治理；“引用存在”仍不能证明证据充分。
Boundary
只验证 join-key 需求；没有两个 workflow 反复消费同一关系，不进入 canonical schema。
6

6. Knowledge Invalidation Canary

Experiment置信度 63%复杂度 Low–Medium

Description：从 3 条已经被真实 workflow 复用的高价值 learning 开始，为每条定义一个可机械观察的 file/version/contract predicate。命中时只输出 stale/advisory 诊断并要求回源，不自动删除、不扫描全库、不建设 mesh 或 memory 平台。

Axis
Protocol、Knowledge 与跨宿主治理
Basis
direct: Knowledge Harness 已要求 source_refs 与 invalidation_condition，同时诚实说明它们仍是 prose/LLM-enforced。reasoned: 只有被实际复用且具有可观察失效信号的 knowledge，才值得从 loud convention 提升为最小 canary。
Rationale
项目长期应拥有的是可失效知识，而不是宿主 session memory。局部 canary 可以验证主动降级是否真的避免错误复用。
Downsides
尚无 stale knowledge 事故率和 consumer 复用量；predicate 容易漂移、误报或无人处理。
Boundary
未证明“命中后避免了 material rework”前，不扩为 mesh；无 consumer 的 learning 不进入实验。
Rejection Summary

被合并或淘汰的方向

对抗性结论：所有“统一图谱、全局状态、自动遥测、通用 conformance runtime、知识 mesh”都被降级或拒绝。当前没有一项达到 Build 门槛。
