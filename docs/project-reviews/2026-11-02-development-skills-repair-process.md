# 研发链路 Skill 审查问题修复流程

日期：2026-11-02。依据：S00 修复实践及用户确认的后续逐项修复方式。

适用范围：[审查报告](2026-11-01-development-skills-review-report.md)第2节总表中的后续问题。本文是执行参考，不新增运行时状态机，不替代当前用户授权、项目角色契约或实际证据。

## 核心方法

**总表选项 → 回源核实 → 方案确认 → 最小修复 → 分层验证 → 独立复核 → 回填状态。**

先明确用户意图和副作用边界，再修正实现或执行顺序，最后以可复核证据验收。历史报告提供线索，当前源码、契约、测试和实际运行结果决定结论。脚本检查确定性事实，LLM 判断语义充分性；文案正确、关键词命中或测试数量不能替代真实行为证据。

## 执行流程

### 1. 确定本轮范围

- 以总表为工作索引，明确当前 S 编号及对应 F 问题。
- 区分本轮必修、必要关联和暂不处理项，不顺手扩大范围。
- 检查工作区现状，保护已有未提交改动；明确修改目标和源码归属。

### 2. 核实问题与根因

- 读取当前源码、契约、消费者和既有测试，复现原问题。
- 区分文案矛盾、实现缺陷、评测缺陷与尚待行为验证的风险。
- 历史描述不准确时先纠正；保留历史观察，不把风险推断写成已发生的损害。
- 记录触发条件、实际结果、预期结果及根因证据。无法复现时记录缺口，不预设修复必然有效。

### 3. 解释问题并确认方案

说明问题影响、根因、最小修改方案、涉及文件、验收标准及未覆盖范围。按当前逐项协作约定，先向用户解释并确认方案；确认后持续完成实施与验证，不重复索取同一授权。

用户后续明确调整为自主推进时，按新授权执行。新增外部写入、费用、发布或其他重要副作用，只确认超出既有授权的部分。

### 4. 先建立失败证据，再修复

- 优先复用既有测试或原始复现；必要时增加能区分正确与错误行为的反例。
- 确认反例因目标缺陷失败，而非环境、夹具或无关前置条件失败。
- 没有合适自动测试入口时，记录可重复的替代验证及其覆盖限制，不为凑测试写关键词断言。
- 对低影响文档改动采用内容、链接及差异检查，不机械要求新增测试。

### 5. 实施最小源码修改

- 修改 source-of-truth，不手改 generated runtime。
- 检查相邻位置及直接消费者是否有同根冲突，只处理与当前问题相关的内容。
- 保持原有合理契约，避免用新审批流程、复杂解析器或通用框架解决局部问题。
- 同步直接相关的示例、评测说明、用户文档和 CHANGELOG。

### 6. 分层验证

| 层级 | 执行内容 | 结论边界 |
|---|---|---|
| 原始复现 | 重跑原始触发场景，确认原症状消除 | 最小测试通过不能代替原问题复验 |
| 确定性回归 | 运行聚焦测试及必要的模式契约、消费者检查 | 只证明实际覆盖的机制与条件 |
| 源码语义 | Skill 正文变更进行 fresh-source 独立审查 | 不等于真实宿主自主行为验证 |
| 宿主与模型行为 | 在授权范围内使用隔离场景、真实工具轨迹及产物验证 | 未执行就标待验证，不用源码审查代替 |
| 实际收益 | 需要真实任务结果才能证明效率、质量等收益 | 本地绿色结果不能外推现场价值 |

只运行当前影响面所需检查。记录实际命令、退出码、日志、目标源码版本和未运行原因；需要模型比较时再绑定模型、宿主、设置与样本条件。不自动挪用历史评测预算。

### 7. 处理复核发现

- 独立复核读取当前磁盘源码；不要依赖本会话缓存的 Skill 定义。
- 对新增发现判断是否属于本轮范围；范围内修复后重跑受影响检查。
- 保留失败、修正及最终结果，不覆盖失败历史或静默改写判据。
- 复核能力不可用时如实记录，不能宣称已通过。必要检查通过后收口，不无限扩展验证。

### 8. 回填报告并交付

- 同步总表状态、复核列、修复结论及相关问题明细，避免一处写完成、另一处仍写待修。
- 记录修改内容、实际验证、独立复核、证据路径和残留事项。
- 修复后源码单独绑定证据；历史审查及其 SHA 清单保持原版本含义。
- 按当前 workflow 要求生成验证与收尾记录；存在未运行项时保留相应降级结论。
- 提交、推送、runtime 刷新和 Provider 安装按实际授权执行，不由“源码修复完成”自动推导。

## 状态与回填模板

状态是证据标签，不是强制状态机。按事实选用：**待处理、待确认方案、修复中、源码修复完成／本地验证通过、行为验证待完成、约定范围已完成**。本地验证通过与行为待验证可以同时成立；完成仅针对明确约定的范围。

每项修复结论统一写为：

> **问题编号：已修复内容；验证方式与结果；独立复核结论；尚未验证或残留事项；证据链接。**

每轮实施记录至少包含：

| 字段 | 要记录的内容 |
|---|---|
| 范围与授权 | S/F 编号、当前目标、已确认方案、明确排除项 |
| 问题与根因 | 原始触发、复现结果、源码或契约依据 |
| 修改 | 具体行为变化、涉及 source、消费者影响 |
| 验证 | 实际命令、结果、证据路径和覆盖限制 |
| 复核 | 当前源码审查结果、发现及关闭情况 |
| 未完成项 | 真实行为缺口、依赖条件、下一步及是否需要新增授权 |
| 交付状态 | 报告回填、runtime 是否刷新、是否提交或推送 |

## S00 示例

- F-S00-01：区分 `--check` 只读检查与 `--verify-only` 的 facts 写入，修正提示而不改变 CLI 模式。
- F-S00-03：先分类请求；纯语义问题移交、诊断用 check、已授权 mutation 先预览；清除参数自身即授权的冲突。
- F-S00-04：移除关键词语义通过，检查标准轨迹及文件哨兵；独立复核发现两处漏检后补反例并修复。机械通过仍需语义审查。
- 结果：4套156项本地测试及独立源码复核通过，真实宿主和双模型行为回归未执行；未刷新 runtime、未提交推送。
