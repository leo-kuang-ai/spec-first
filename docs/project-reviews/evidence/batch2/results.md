### 6.4 S07：评测设施缺陷与重新筛查

skill-up 的 `git: init: true` 不创建初始提交。因此 `apply_diff` 只是改动了未跟踪文件，仓库中没有可审查的 diff。证据：codex 的 transcript 中出现 `fatal: your current branch 'main' does not have any commits yet`。

影响：
- 第二轮筛查中 S07 三个场景的结论无效；
- 第二批中 gpt 的 S07 两组结论也无效；
- GLM 的 S07 阶段在执行前已停用。

修正方法：fixture 目录内自带 `.git` 和一次基线提交。用假的 `claude` 可执行文件验证过：工作区中 `git diff --stat` 显示 2 个文件改动。

用修正后的 fixture 重新筛查（GLM，基线组）：C1、C2、C3 都通过。基线组调用了 Claude Code 内置的 `code-review`，并分别指出了 `floor`、`daily` 和分页缺陷。**S07 目前没有有区分力的场景。**

这个缺陷对其他场景的影响：所有 fixture 都是“无提交、全部未跟踪”的状态。`spec-work`、`spec-debug` 中保护已有未提交改动的规则可能被触发，这是第一批和第二批加载 Skill 一组的一个未量化混杂因素。
