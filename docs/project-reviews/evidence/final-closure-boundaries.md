## S00 / S20 指令工程适用性

S00原分析中“外部内容标记不适用”过宽，应收窄为“不承担PR评论/网页指令的业务处理”。`skills/spec-runtime-setup/SKILL.md`的项目图谱与facts边界明确provider候选不是confirmed truth；setup只准备确定性事实，doctor消费者核对身份、source与receipt。外部provider输出仍需要来源和不可信边界，不能因为不是PR内容就豁免。已读状态/lease/事实消费者证据见两份final-S00补审。该设计不证明任意provider内容在宿主中已硬隔离。

S00子代理条目不适用的理由：主要执行者是确定性setup脚本，当前职责不要求由多个语义agent协商安装权限；授权、路径、exact配置、回读与失败恢复由脚本和owner边界承担。对脚本复杂性的独立源码复核仍适用，不能用“不适用”免除验证。已读SKILL和refs要求输出facts、reason_code、具体阻塞与下一步，没有要求逐字输出内部思维；原“统计0”只是定位线索，不能单独证明语义合格。硬约束应保留在真实host mutation、来源身份、facts真实性和失败恢复出口；不建议添加通用“再仔细想一次”。

S20补充“硬约束与验证要求的区分”：`skills/using-spec-first/SKILL.md` Exit Boundaries明确路由选择不产生写入、完成声明、runtime维护、handoff或landing授权；Fast Paths允许活跃owner继续，不为普通续作重启路由。前者是出口边界，应保留；恰好选择一个owner是入口分工偏好，不是模型推理过程的硬状态机。“任务未跑也不能编造结果”与“模型每步再自我检查一次”不同，不能为了降成本一起删除。现有源文无逐字思维输出要求，路由应给简短理由及下一步即可。

## 全部结论的重评规则

本节明确适用于S00–S21及所有历史行为批次，补充各分组未重复展开的共同条件：

1. 更换模型、模型版本、provider或effort时，重新记录组合并重测受影响行为；同名effort不保证相同思考量。未记录的历史effort保持unknown，不能从今天的配置推断。
2. 更换宿主/版本、可用subagent、内置Skill、MCP、浏览器/Xcode或关键工具状态时，重新检查环境与对照隔离；一次版本探测不等于评测可用。
3. 目标Skill正文、必读引用、相关脚本/合同或真实consumer内容变化时，对照SHA定位影响，重评相关语义及场景。hash未变且范围未变可以复用阅读；不能把日期刷新当验证刷新。
4. 业务输入、fixture、历史Git基线、prompt、oracle或评判条件变化时，视为新实验条件，保留旧失败/无效样本，不合并成一项可直接比较的成功率。
5. 新增反例、真实任务结果与现有结论冲突时降级对应claim；不因源码静态合理或测试绿色压制反例。真实企业效果仍未验证，不能宣称本报告证明全局提效。

原始耗时、轮次、token字段按原记录保存；无法追回的审查者活跃工时和effort明确缺失。这里规定未来可复核条件，不伪造已经具备历史可重放性。任何历史元数据缺口对严格验收的影响由主报告单独保留，不能用这份补充自动豁免。
