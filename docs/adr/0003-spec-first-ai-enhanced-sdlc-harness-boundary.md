# ADR 0003: spec-first 采用 AI-enhanced SDLC Harness 连接层定位

- 状态：accepted
- 日期：2026-09-09
- 决策来源：本次用户确认选择 A
- 相关：[`docs/10-prompt/结构化项目角色契约.md`](../10-prompt/结构化项目角色契约.md)、[`docs/contracts/ai-coding-harness.md`](../contracts/ai-coding-harness.md)

## 背景

`spec-first` 已经具备从意图、规格、计划、任务到代码、审查、证据和知识沉淀的研发主链路。需要明确的是：产品是否应进一步成为一个统一负责项目管理、发布、部署、生产运维和运营反馈的完整 AI-DLC 平台，还是继续以项目原生 Harness 的方式增强 SDLC 并连接已有工程系统。

如果只把名称改成 AI-enhanced SDLC，容易扩大用户预期；如果直接建设完整生命周期平台，则会引入项目组合治理、团队权限、跨系统状态一致性、发布编排、生产遥测和事故响应等新的系统责任。

## 决策

采用 **A：AI-enhanced SDLC 的研发 Harness 和连接层**。

`spec-first` 负责 AI 驱动的研发判断、变更编排、证据链和知识复用，目标是缩短从正确意图到可信变更的时间。项目管理、代码托管、CI/CD、部署、监控和事故系统继续保有各自的状态权威。

这不是把产品限制在代码生成，而是把责任集中在最有差异化、最可验证的研发变更闭环，并通过适配器逐步连接 SDLC 外围系统。

## 目标边界

### spec-first 负责

- 需求意图、规格、技术方案、任务、实现和审查之间的连续性；
- 项目源码、约束、影响面和历史决策的有界上下文；
- AI 语义判断、人工授权、交接和恢复所需的 workflow；
- `change_id`、来源、freshness、claim 和 verification evidence；
- review 返工、验证结果和后续经验的可回源知识沉淀；
- 外部系统事实的关联、摘要、建议和必要的受控写回。

### 外部系统负责

- 项目优先级、团队排期、资源和组织治理；
- 代码版本、构建和持续集成状态；
- 发布、部署、环境变更和回滚执行；
- SLO、监控、告警、事故响应和生产运行状态。

`spec-first` 不复制外部系统的完整生命周期状态，不建设第二套项目管理或生产运维平台，也不因消费外部证据而声称拥有对应系统的运行责任。

## 目标架构

```text
需求 / 项目系统
        ↓
spec-first
意图 → 规格 → 方案 → 任务 → 实现 → 审查 → 证据 → 知识
        ↓
代码仓库 / CI / 发布 / 部署 / 监控
        ↑
     结果反馈
```

连接器默认先采用只读消费，建立来源、权限、freshness、失败和降级语义；需要写回时，只写链接、状态摘要、评论或交接结果，避免与外部权威产生竞争。

## 升级顺序

### 阶段一：强化研发主链路

稳定 `Spec → Plan → Tasks → Work → Review → Knowledge` 的 ID、状态、证据和 freshness，确保计划、任务、实现和审查可以相互追踪。

### 阶段二：打通代码与交付事实

接入代码仓库、CI 和测试结果，形成从需求到合并变更的连续追踪；先验证减少上下文丢失、交接等待和 review 返工。

### 阶段三：接入发布与运行反馈

消费部署、监控和事故信息，形成发布后验证和知识回流；这些系统仍由原 owner 负责执行和确认。

### 阶段四：用真实结果调整边界

在代表性项目中比较上下文恢复时间、需求返工率、review 返工率、验证失败率、交接耗时和问题逃逸率。只有真实结果证明新增责任带来净收益，才扩大自动化或集成深度。

## 非目标

- 不把所有 workflow 强制串成固定状态机；
- 不以 artifact 数、token 数或 agent 数代表 SDLC 价值；
- 不把测试通过、自检或模型信心包装成生产结果；
- 不在缺少权限、来源和现场证据时自动执行外部副作用；
- 不因“AI-enhanced SDLC”命名而默认承诺完整 AI-DLC 能力。

## 重新评估 B 的条件

只有同时出现以下事实，才重新评估是否让 `spec-first` 承担更广泛的生命周期责任：

1. 存在明确的组织级用户、业务 owner 和长期维护责任；
2. 项目管理、发布、部署和运营系统提供稳定且可授权的接口；
3. 已验证跨团队、多项目的真实场景，而不是单仓库推演；
4. 有生产结果数据证明统一生命周期治理带来净收益；
5. 已建立权限、状态一致性、失败恢复、审计和退出机制。
