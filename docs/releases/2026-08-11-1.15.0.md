## 摘要

spec-first 1.15.0 让团队可以把初始化时选择的宿主 runtime 作为项目交付内容共同维护，同时增强高风险变更从计划、执行到审查和收口的证据连接。

## 亮点

- `spec-first init --<host>` 生成的 skills、agents、commands、hooks、pointer 与 state 默认保持 Git 可见，可随用户项目提交和复用。
- `.gitignore` 只继续管理本地缓存、scratch 和 provider artifacts，不再替团队决定哪些宿主 runtime 必须留在仓库之外。
- 高风险工作现在更明确地连接 proof intent、evidence authority、source binding 与 required-proof reconciliation。

## 新增

- selected host 继续只决定生成范围，无需维护额外的 Git disposition 状态或第二套 manifest。
- 计划、执行和代码审查获得更清晰的风险到验证映射，并能区分转录结果、provider 确认证据与最终源码绑定。
- Xcode 验证结果补充 target、source identity、freshness、limitations 和 claim ceiling 边界。

## 修复

- init 不再自动修改 Git index membership，升级时只替换 spec-first 管理的 `.gitignore` block。
- reset、drift repair、clean 与 legacy command cleanup 只处理 spec-first 精确拥有的条目，避免删除团队维护的 sibling 文件。
- Claude、Codex 与 Qoder hooks 不再固化生成机器的项目根、安装位置或 Node 绝对路径。
- requirements replay 与 run artifact latest selection 不再依赖易受 squash、路径大小写或 mtime 精度影响的隐含条件。

## 破坏性变更

- 没有 CLI 参数或 artifact schema 的破坏性变更。升级后重新运行 `spec-first init --<host>` 时，先前被默认忽略的 selected-host runtime 会出现在 `git status` 中，这是本版本的预期行为。

## 升级注意事项

- 升级后建议运行一次 `spec-first init --<host>`，检查 `.gitignore` diff 和 `git status`，再由团队决定提交生成的 runtime。
- init 不会自动 stage、commit 或执行 `git rm --cached`，现有 index membership 保持不变。
- 若项目在 managed runtime 目录中维护自定义 sibling 文件，reset 和 clean 应保留这些非 spec-first-owned 内容。
