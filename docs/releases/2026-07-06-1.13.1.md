## 摘要

本版是 `spec-first` 1.13.0 的 patch 修复，收敛 1.13.0 发布之后累积的一批 Windows / CLI 兼容性与安装流程修复。核心是修复 Claude 宿主 hook 在 Windows（尤其无 Git Bash 环境）下无法运行的问题，并顺带修复 Windows 文件写入竞争、npm 安装 smoke 的命令行转义，以及 `spec-first init` 在父级多仓 workspace 与缺少 developer 身份时的行为。无破坏性变更，可直接升级。

## 亮点

- Claude 4 个 managed hook（`session-start`、`spec-plan-guard`、`prd-prewrite-guard`、`prd-readiness-guard`）从 bash-shebang 脚本重写为跨平台 Node 脚本，`.claude/settings.json` 改用 exec form（`command: "node"` + 项目根相对 `args`）。此前 Windows 无 Git Bash 时这些 hook 会静默失效，本版使其在 macOS / Linux / Windows（有无 Git Bash 均可）行为一致。
- `spec-first init` 在父级多仓 workspace 下默认只初始化父 workspace runtime，不再逐个 child Git repo 生成 host runtime；`init -y` 在缺少 developer 身份来源时以可执行提示（带 `-u <name>`）退出而非直接失败。
- `spec-mcp-setup` 与 `spec-rule-miner` 的 handoff 边界明确化：Runtime Setup 只负责 provider readiness，规则挖掘由用户单独运行 `spec-rule-miner`，setup 不自动合成规则或写 `docs/ai/project-rules.md`。

## 修复

- 修复 Claude hook exec-form 的 `$CLAUDE_PROJECT_DIR` 全平台回归：exec form 下 Claude 不展开该变量，字面量被 node 相对 cwd 解析成不存在路径导致 `MODULE_NOT_FOUND`；改用项目根相对 hook 路径，hook 自身从 `CLAUDE_PROJECT_DIR` env / cwd 解析项目目录。
- 修复 hook 刷新去重：removal 逻辑同时识别相对路径与 legacy `$CLAUDE_PROJECT_DIR/` 前缀 exec-form hook，`spec-first init` 刷新时替换而非叠加，避免 `settings.json` 出现重复 matcher。
- 为 `writeFileAtomic` 的 `renameSync` 增加 Windows 瞬时占用（EPERM/EACCES/EBUSY，杀毒/索引器/句柄争用）重试，减少 `spec-first init` 在 Windows 偶发的写入硬失败。
- 修复 npm 安装矩阵 smoke 在含空格路径下的 Windows `cmd.exe` 命令行双重转义（`windowsVerbatimArguments`）。
- `spec-mcp-setup` verify-tools 宿主契约与 `spec-rule-miner` SKILL/references/eval 细化。

## 升级注意事项

- 直接升级即可，无破坏性变更：`npm install -g spec-first`。
- 升级后建议运行 `spec-first init` 刷新本地宿主运行时资产——尤其从 1.13.0 升级的用户，需借此把 `.claude/settings.json` 的 hook 命令刷新为修复后的跨平台 exec form。
- Windows 用户：本版后 Claude hook 不再依赖 Git Bash；`spec-first init` 的文件写入在杀毒/索引器占用下更稳健。
- 完整清单请参阅 CHANGELOG 或 git log（`v1.13.0..v1.13.1`）。
